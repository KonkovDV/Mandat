# Реестр утверждений

Каждое число и сильное утверждение для презентации и питча — с командой, которая его воспроизводит, и границей. Главное правило: говорим только то, что есть в этой таблице, и называем номер строки. Сверено с `evidence.json` и открытыми источниками 15.10.2026.

Текст презентации и всех документов проверяет `python scripts/lint_claims.py` по списку `BANNED_CLAIMS.txt`. Как проговорить это в зале — [сценарий показа](docs/DEMO.md).

## О продукте (проверяется командой)

| № | Утверждение | Как воспроизвести | Граница |
|---|---|---|---|
| C-01 | 39 правил, у каждого норма, следующий шаг и тест | `python scripts/gen_rules_doc.py`, тест `test_every_rule_traces_to_an_existing_test` | все в статусе `draft`, юрист банка не утверждал |
| C-02 | 14 демо-кейсов дают ожидаемые вердикты, «подтверждено» — один (кейс 14) | `mandat demo` | данные вымышлены; отметка об уставе в кейсе 14 синтетическая |
| C-03 | Корпус 294 кейса (49 видов): совпадение 294 из 294; ложных «подтверждено» 0 из 288, верхняя граница 95 % — 1,3 %; по видам дефектов 0 из 48, граница 7,4 % | `mandat eval --per-defect 6`; отложенный seed — `synthetic_corpus_holdout` в evidence.json | проверка логики на сгенерированных документах, не точность на документах банка; кейсы одного вида зависимы |
| C-04 | Все 108 опровергающих кейсов распознаны, нижняя граница полноты 96,6 % | то же | то же |
| C-05 | Без человека решается 38,8 % корпуса, ошибок среди них нет, верхняя граница риска 3,2 % | то же | доля задана составом корпуса; в `strict` — 0 % |
| C-06 | Передоверие не расширяет полномочия на всех 384 двухзвенных цепочках; вторая реализация на Cedar даёт те же решения | `python -m pytest tests/test_properties.py tests/test_cedar.py` (нужен extra `cedar`) | перебор малого домена, а не доказательство для любых входов |
| C-07 | Одинаковые документы и правила дают одинаковый хеш отчёта | `mandat demo` дважды, сравнить `reproducibility_hash` | при той же версии движка; время формирования в хеш не входит |
| C-08 | Языковая модель не меняет вердикт | тесты `test_advisory_cannot_change_verdict`, `test_advisory_finding_cannot_change_verdict` | про код «Мандата», не про качество модели |
| C-09 | Журнал обнаруживает правку или удаление записи и доказывает включение одной записи | `mandat journal-verify var/demo/journal.jsonl`, `mandat journal-proof var/demo/journal.jsonl --seq 3` | защита от правки файла, а не от кражи ключа |
| C-10 | Удостоверение проверяется без доступа к базе, вместе со статусом «действует / приостановлено / отозвано» | `mandat attest-verify var/demo/attestations/01_ok.json --public-key "$(cat var/demo/public_key.txt)" --status-dir var/demo/status` | подпись Ed25519, не ГОСТ; с внешними верификаторами не проверялось |
| C-11 | Отмена основной МЧД отзывает удостоверения по всей цепочке; признаки захвата их приостанавливают | `mandat monitor examples/events/poa_revoked.json --status-dir var/demo/status`, тест `test_monitor_revokes_and_suspends_attestations` | события из файла; права в ДБО (дистанционное банковское обслуживание, интернет-банк) не меняются |
| C-12 | Работает без внешней сети | `mandat demo` без сети; модель выключена, пока не задан `MANDAT_LLM_BASE_URL` | — |
| C-13 | Все автотесты проходят | `python -m pytest` | число — в `evidence.json` |
| C-14 | Проверка кейса с разбором документов — единицы миллисекунд (медиана около 2 мс) | `python scripts/bench.py` | машина разработчика, без сети и модели; в банке — замер на его контуре |
| C-15 | Сценарий высвобождения: 33 / 75 / 167 ставок в год | `python scripts/effect_model.py --scenarios`, поле `fte` | доли событий и минуты — допущения команды, не прогноз |
| C-16 | Сценарий предотвращённого ущерба: 34 / 115 / 229 млн руб. в год | `python scripts/effect_model.py --scenarios`, поле `prevented_loss_mln_rub` | доля ВТБ и доля инцидентов с полномочиями — допущения команды |
| C-17 | 8814 мутированных сценариев: ни одного ложного «подтверждено» и ни одного падения | `python -m pytest tests/test_redteam_fuzz.py` | мутации построены от наших же базовых сценариев; число закреплено в тесте и сверяется `scripts/lint_claims.py` |

## Как нельзя и как можно

| Нельзя | Можно |
|---|---|
| «ИИ принимает решение», «ИИ определяет полномочия», «модель выносит вердикт» | «правила выносят вердикт, модель подсказывает факт с цитатой, спорное решает сотрудник» |
| «юридически значимая проверка» | «доказательная поддержка решения сотрудника» |
| «права выдаются автоматически», «автоматически отзывает права» | «рекомендует роль; при событии меняет статус удостоверения» |
| «проверка КЭП выполнена», «проверяем КЭП по ГОСТ» | «порт проверки КЭП готов к подключению СКЗИ (средство криптографической защиты информации) банка» |
| «интегрирован с реестром ФНС» | «порт реестра готов, в стенде — заглушка» |
| «смена директора аннулирует доверенности» | «смена директора доверенность не прекращает; свежая смена — повод для разбора» |
| «соответствует 152-ФЗ», «соответствует ГОСТ Р 57580», «соответствует приказу ФСТЭК (Федеральная служба по техническому и экспортному контролю)» | «спроектировано с учётом 152-ФЗ: работа в контуре банка, псевдонимизация, минимизация» |
| «гарантируем отсутствие мошенничества» | «снижаем риск захвата и действий по оборванной цепочке» |
| «точность 99%», «100% точность» | цифры C-03…C-06 с границей |
| «внедрено в ВТБ», «одобрено ВТБ» | «готовы обсуждать теневой пилот на обезличенных кейсах» |
| «ВТБ не умеет», «никто на рынке не умеет» | «в открытых источниках не нашли продукта, который сводит МЧД, ЕГРЮЛ (Единый государственный реестр юридических лиц) и устав в один вердикт на дату» |
