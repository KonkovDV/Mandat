# Сверка JCS и base58btc с независимыми реализациями

Эксперимент аудита 27.10, а не тест пакета: эталоны в lock-файлах не закреплены и в CI не ставятся. Вопрос: пишет ли `audit/jcs.py` те же байты, что независимая реализация RFC 8785, и совпадает ли base58btc удостоверений с распространённой библиотекой.

## Как повторить

```bash
python -m venv .venv-jcs && .venv-jcs/bin/pip install -e . rfc8785==0.1.4 base58==2.1.1 hypothesis
.venv-jcs/bin/python tools/experiments/jcs_differential/run.py
```

## Эталоны

- [`rfc8785`](https://github.com/trailofbits/rfc8785.py) 0.1.4, Trail of Bits — реализация RFC 8785 на Python.
- [`base58`](https://github.com/keis/base58) 2.1.1 — base58 с алфавитом Bitcoin, тот же, что у `z` в multibase.

## Результат

- 20 000 случайных документов JSON (вложенные объекты и массивы, строки без суррогатов, конечные числа, целые до 2**53 − 1) и 20 000 чисел дали те же байты.
- 5000 случайных строк base58btc совпали, обратное преобразование их восстановило.
- До исправления 27.10 «Мандат» принимал целое 2**53, а `rfc8785` его отвергает (`IntegerDomainError`). По RFC 7493 (разд. 2.2) точны только целые из [−(2**53) + 1, 2**53 − 1], поэтому граница сдвинута на единицу. Числа двойной точности это не затронуло.

Разбор — [аудит 27.10, сверка с эталонами](../../../docs/audit/AUDIT-2026-10-27-DIFFERENTIAL.md).
