# Безопасность

## Как сообщить об уязвимости

Напишите автору через GitHub (личное сообщение или приватный security advisory в репозитории). Не публикуйте детали в открытых issue, пока исправление не выпущено. Ответ — в течение трёх рабочих дней.

## Что уже сделано

- XML разбирается через `defusedxml`: запрещены DTD, внешние сущности, ограничены размер, число элементов и глубина (`intake/xml_safety.py`).
- Загрузка кейса из папки не выходит за её пределы (тест `test_case_loader_blocks_path_traversal`).
- HTTP API закрыто по умолчанию: без `MANDAT_API_TOKEN` отвечает 503, с неверным токеном — 401; лимит тела запроса 8 МБ; отчёт отдаётся с заголовком CSP.
- HTML-отчёт экранирует все данные кейса.
- Модель вызывается только на хосты из `MANDAT_LLM_ALLOWED_HOSTS`, текст перед отправкой псевдонимизируется.
- Журнал решений — хеш-цепочка с HMAC и файлом-свидетелем последней записи; дерево Меркла даёт доказательство включения одной записи.
- Удостоверения и списки статусов подписаны; при проверке статуса подпись списка проверяется, подменённый список отвергается.
- Контейнер работает от непривилегированного пользователя; CI — с правами только на чтение.

## Секреты

`MANDAT_JOURNAL_KEY`, `MANDAT_PII_KEY`, `MANDAT_API_TOKEN`, ключ подписи удостоверений. В репозиторий не кладутся; пример — `.env.example`. Ключи по умолчанию предназначены только для разработки.

Модель угроз — `docs/THREAT_MODEL.md`.
