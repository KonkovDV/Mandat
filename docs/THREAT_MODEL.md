# Модель угроз

Черновик для согласования с ИБ банка: что может пойти не так, чем это закрыто в коде и что остаётся банку. Самые важные остатки — проверка КЭП через СКЗИ, связь с антифродом, ключ подписи в HSM или KMS банка и приёмник внешнего якоря журнала. Адаптеры для ключа и якоря в коде есть.

| Угроза | Пример | Мера в коде | Что остаётся |
|---|---|---|---|
| Подделка доверенности | МЧД с чужим доверителем или подписантом | сверка доверителя с клиентом, подписанта с ЕГРЮЛ на дату выдачи, статус в реестре | проверка КЭП через СКЗИ банка |
| Захват компании | смена руководителя, новая МЧД и смена реквизитов | свежая смена — «на разбор», тревога `possible_takeover`, приостановка удостоверений организации | связь с антифродом банка |
| Оборванная цепочка | основную МЧД отменили, передоверие осталось | каскад по п. 3 ст. 188 ГК РФ (R-SUB-006), отзыв удостоверений по событию | задержка события из реестра |
| Устаревшее удостоверение | права проверены месяц назад, МЧД уже отменена | список статусов W3C: проверяющий видит «отозвано» или «приостановлено» | частота обновления списков |
| Слабый профиль | клиент запускает проверку в `demo` вне стенда | вне `demo`/`dev`/`test` допускается только `strict`; удостоверение demo в защищённом режиме не принимается | — |
| Инструкции в документе (OWASP LLM01:2025) | текст для модели внутри устава | маркеры данных, их копии вычищаются из текста; модель не меняет вердикт, без дословной цитаты нет факта | — |
| XML-бомба, внешние сущности | DTD с сущностями | `defusedxml`, лимиты размера, глубины и числа элементов | — |
| Неоднозначный JSON | повтор ключа, NaN, сверхглубокий документ | `strictjson` на внешних входах: ошибка входа, а не последнее значение и не падение | ответ read-back якоря читает обычный `json.loads` ([#131](https://github.com/KonkovDV/Mandat/issues/131)) |
| Нечестный приёмник якоря | получатель вебхука на read-back отдаёт документ, от которого проверка падает | подпись ответа, сверка sha256 и `delivery_id` | слишком глубокий ответ не становится «не разбирается», а роняет проверку ([#131](https://github.com/KonkovDV/Mandat/issues/131)) |
| Подделка или повтор события | чужое или повторное событие мониторинга | Standard Webhooks: HMAC-SHA256 или Ed25519, окно ±5 минут, метка не длиннее 12 цифр; в `pilot` и `prod` без хранилища повторов событие отклоняется | секрет `MANDAT_WEBHOOK_SECRET` и общее хранилище повторов задаёт банк |
| Подмена пакета | колесо или sdist не из `main` | аттестация SLSA и SBOM, действия по полному хешу коммита, зависимости по хешам lock-файлов | банк сам запускает `gh attestation verify`; релизов нет, артефакт CI хранится 30 дней ([проверка](../SECURITY.md#проверить-пакет)) |
| Обход каталога | `"path": "../../etc/passwd"` | путь документа не выходит за каталог кейса | — |
| Правка журнала | изменение, удаление, обрезка записей | хеш-цепочка, HMAC (обязателен в `pilot` и `prod`), файл-свидетель, сверка корня Меркла с сохранённой копией (`--merkle-anchor`) | правку вместе с ключом и свидетелем ловит только внешний якорь (строка ниже) |
| Переписанная история | root на хосте меняет сегменты, свидетель и ключ вместе | внешний якорь закрытых сегментов (`MANDAT_JOURNAL_ANCHOR`): метка времени RFC 3161, Sigstore Rekor, приёмник банка; `journal-verify` требует квитанцию на каждый сегмент | выбрать приёмник банка и включить `MANDAT_JOURNAL_ANCHOR_POLICY=fail` |
| Подмена удостоверения | правка вердикта в JSON | подпись Ed25519, проверка издателя, назначения и срока | открытый ключ банка, ГОСТ-подпись |
| Кража ключа подписи | ключ читают с диска сервера | в `pilot` и `prod` открытый PEM запрещён; HSM по PKCS#11, Vault Transit или AWS KMS; связка ключей с отзывом | HSM или KMS банка |
| Повтор удостоверения | одно удостоверение предъявлено дважды или на другую сумму | `authorize_operation` сверяет сумму, представителя, получателя и одноразовый `nonce` | общее хранилище `nonce` у интегратора |
| Удостоверение не на ту операцию | удостоверение на прошлую дату, на другую компанию того же представителя или после истечения МЧД | дата сверяется с днём проверки по Москве, организация — с ИНН, срок удостоверения не длиннее 30 дней и не длиннее самого раннего срока документа цепочки, если эти сроки в отчёте есть | без сроков в отчёте истечение МЧД видно только по событию `POA_EXPIRED`; удостоверение руководителя без МЧД отзывается только когда `mandat monitor` получит событие `EIO_CHANGED` ([#124](https://github.com/KonkovDV/Mandat/issues/124)); момент проверки берётся из аргумента `now`, его ставит сервер |
| Недописанный ключ | процесс упал при записи ключа | временный файл 0600, fsync, публикация жёсткой ссылкой; существующий ключ не перезаписывается | KMS или HSM в пилоте |
| Утечка ПДн (OWASP LLM02:2025) | ИНН или ФИО в запросе к модели | метки ФИО, псевдонимизация HMAC, белый список хостов | DLP банка |
| Доступ к API без прав | запрос без токена | без токенов 503, с неверным 401, сравнение за постоянное время, Swagger выключен | OIDC банка |
| Чужой кейс | оператор читает кейс коллеги | роли и владельцы, `case_id` от сервера, на чужое 404 | OIDC банка |
| Перегрузка API | поток запросов с одного адреса | 120 запросов в минуту, тело до 8 МБ, до 1000 отчётов, общий лимит через SQLite или Redis; сверх 64 одновременных соединений `mandat serve` сразу отвечает 503 | лимит на шлюзе банка |
| Доверитель в банкротстве | доверенность после открытия конкурса | R-EIO-004 через `BankruptcyPort`, данные из кейса | адаптер ЕФРСБ |
| Слежка по списку статусов | по номеру бита виден порядок выдачи | случайные номера, список не меньше 131 072 бит | раздача списка без логов |
| Ложное «подтверждено» | реестр недоступен | недоступность даёт «недостаточно данных» | калибровка на пилоте |

Меры подробнее — [SECURITY](../SECURITY.md), персональные данные — [DATA_PROTECTION](DATA_PROTECTION.md).
