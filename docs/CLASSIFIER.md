# Снимок классификатора полномочий ФНС

Код: `src/mandat/rules/classifier.py` (`import_kpmp`), правило R-COV-002 (`src/mandat/rules/checks.py`);
тесты: `tests/test_sota_m1_kpmp_classifier.py`.

## Источник

ФНС публикует копию единого классификатора полномочий для МЧД из ЕСНСИ:
`GET https://kpmp.nalog.gov.ru/authority-classifier-idmz/api/v1/GetAllRecords`. Ответ — JSON с полями
`groupRecords` (группы), `classRecords` (коды полномочий) и `date` (момент выгрузки, UTC). Выгрузка от
15.10.2026: 315 групп и 2837 записей, 2638 разных кодов.

«Мандат» в этот сервис не ходит: ни в работе, ни в CI. Выгрузку скачивают отдельно и превращают в снимок:

```bash
curl -o GetAllRecords.json https://kpmp.nalog.gov.ru/authority-classifier-idmz/api/v1/GetAllRecords
python scripts/import_classifier.py GetAllRecords.json --out var/classifier-YYYY-MM-DD.json
```

В снимок записываются момент выгрузки (`snapshot_at`), имя файла и его sha256 (`source`). В репозитории лежит
только вырезка из настоящей выгрузки для тестов: `tests/fixtures/kpmp/GetAllRecords-2026-10-15-sample.json`,
её sha256 проверяется тестом. Полный снимок (около 1,2 МБ; по выгрузке от 15.10.2026 — 2638 кодов, из них два неоднозначных: `FK9800_GIISEB_EB10019`, `FK9800_ISUC_UC0001`) в репозиторий не кладётся: его хранит банк вместе с
датой и хешем, а снимок стенда остаётся синтетическим.

## Даты

Даты ФНС — моменты в UTC: `2023-08-29T21:00:00Z` — это 30.08.2023 00:00 по Москве. В снимке они хранятся в UTC
с поясом, а действие кода на дату выдачи МЧД и дату операции сравнивается по календарной дате в
Europe/Moscow. Дата без времени и пояса в выгрузке ФНС — ошибка импорта.

## Повторы кодов

В выгрузке код может встречаться несколько раз (в выгрузке от 15.10.2026 — пять кодов, 199 лишних записей):

| Повторы | Что делает импорт |
|---|---|
| полностью одинаковые | одна запись, повтор пишется в журнал (`classifier_duplicate_collapsed`) |
| различаются только группой | одна запись со списком групп (`groups`) |
| различаются по существу (название, даты, мнемоника и т. д.) | код помечается `ambiguous`, название и даты не берутся (`classifier_code_ambiguous`) |

МЧД с неоднозначным кодом всегда уходит на разбор человеку (R-COV-002), даже если для операции этот код не
нужен: какая из записей верна, правило не выбирает.

## Возраст снимка

Снимок верен на момент выгрузки: исключение кода после неё он не покажет. Если операция позже снимка больше чем на
`MANDAT_CLASSIFIER_MAX_AGE_DAYS` дней (по умолчанию 3, целое от 0 до 365), R-COV-002 отправляет МЧД на разбор.
Значение по умолчанию не взято из норм и не выведено из частоты обновления сервиса: данных для этого
недостаточно. Что известно на 16.10.2026:

- график обновления ФНС не публикует; в открытых описаниях сервиса (с 16.12.2025) частота не названа;
- поле `date` — момент выгрузки: в двух ответах 16.10.2026 (около 07:20 и 08:02 по Москве) оно одинаковое,
  `2026-10-15T19:04:33Z`, и сами ответы совпадают байт в байт (sha256 `d44b6077…bc11d`). Значит, ответ
  собирается не на каждый запрос, но как часто — по двум наблюдениям за один день сказать нельзя;
- даты `started` показывают, как часто появляются новые коды, а не как часто обновляется выгрузка: с
  16.10.2025 коды вводились в 51 разный день, промежуток между такими днями — от 1 до 19 дней, медиана 5;
  последний новый код введён 01.10.2026. Даты исключения (`revoked`) в выгрузке не заполнены ни у одной записи,
  поэтому о частоте исключений по ней судить нельзя.

Поэтому 3 дня — осторожный инженерный выбор: меньше медианного промежутка между днями ввода новых кодов и
больше суток: снимок, который банк выгружает раз в сутки, проходит с запасом на сбой выгрузки. Банку стоит
следить за полем `date` и задать допуск по собственному графику выгрузки.

## Прошлые даты

У сервиса есть параметр `date`, но справочник на прошлую дату он не возвращает: на `?date=2024-01-01` (проверено
16.10.2026) приходит пустой ответ с `date` = `0001-01-01T00:00:00`, и импорт его отклоняет. Поэтому для проверки
старых операций нужен снимок, сохранённый тогда же: банк хранит снимки с датой и хешем, а текущий снимок для
прошлых операций не годится (исключённый с тех пор код может просто пропасть из выгрузки).
