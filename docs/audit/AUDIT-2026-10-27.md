# Глубокая проверка, 27.10.2026

Проверка дерева `9386cc4`. Срезы 20.10, 22.10 и 26.10 не переписываются. Код допуска, строгий JSON и канонизация с этого коммита не менялись. Хеш исходников в `evidence.json` по-прежнему `fc9c746f0fe1a43467beaf90403ecbf39b67b2f3918c44f66c261b77644cffc3`. Число автотестов там 1491, от прогона 16.10.

Шкала: **К** критично, **В** высокая, **С** средняя, **Н** низкая.

## Что прогнано заново

| Проба | Результат |
|---|---|
| `strict_loads("1e309")` | `inf`. Литерал `Infinity` по-прежнему отвергается |
| Строка с U+2028 | принимается. Канонизация JCS оставляет символ как есть: RFC 8785, раздел 3.2.2.2, требует именно этого, а не `\u2028` |
| Целое из 401 цифры | остаётся `int`. В подпись такое число не попадает: JCS отвергает целые вне ±2^53 |
| Срок `not-a-date` | окно не сокращается: `2026-10-20` → `2026-11-19` |
| Срок `9999-12-31` | `OverflowError` в `_authority_end`, выпуск не завершается |
| 20.10 21:00 UTC | это уже 21.10 по Москве. Сверка дня смотрит на день запроса, не на календарь выпуска |
| Lock-файлы | `certifi` 2026.10.23, `pip` 26.2.2, `setuptools` 84.2.1. Это выпуски после PYSEC-2026-4320 и GHSA-xmj3-9gf7-h52w |

Открытых PR нет. Кроме `main` на GitHub остаётся ветка `docs/audit-2026-10-22`: её дерево совпало со сквошем `9386cc4`.

## Red Team

Чужой день, чужая организация и нулевое окно при уже прошедшем сроке держатся так, как записано 20.10 и 22.10. Новые дыры другие.

Разбор МЧД принимает дату `9999-12-31` (`intake/emchd.py` сверяет только форму `ГГГГ-ММ-ДД`). Год `>= 9999` отсекается лишь когда срок вычисляется по ст. 186 ГК РФ и даты окончания в документе нет. Если дата окончания записана, `issue` прибавляет сутки и падает. Это не отказ: вызывающий получает исключение. Такой год встречается как заглушка «без конца».

Нечитаемая строка срока пропускается молча. Поле в отчёте есть, а окно остаётся 30 днями, как будто срока не было. Для отчёта, собранного движком, дата либо разобрана, либо разбор МЧД уже отверг файл. Дыра открыта для отчёта, который собрали вручную и отдали в `issue`.

U+2028 не ломает подпись относительно RFC 8785. I-JSON (RFC 7493) такую неэкранированную строку не хочет. Это сосед [#122](https://github.com/KonkovDV/Mandat/issues/122), не отдельный обход допуска.
