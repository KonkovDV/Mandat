# Потоки данных, доверенные границы и нарушители

Описано текущее состояние кода. Где поведение исходной версии было другим, это сказано в `AUDIT.md`.

## Основной поток

Клиент или оператор → приём (`intake/case_loader.py`, `emchd.py`, `egrul.py`, `charter.py`) → источники через порты (`ports.py`, `services/verify.py::default_ports`) → граф полномочий (`domain/graph.py::build_chain`) → правила (`rules/checks.py`, `rules/pack.py`) → свёртка (`domain/verdict.py::fold`) и независимая свёртка (`domain/verdict_oracle.py`) → отчёт (`CaseReport`, `report/html.py`) → журнал (`audit/journal.py`, `audit/merkle.py`) → ручной разбор (`review/state_machine.py`) → удостоверение и статус (`audit/attestation.py`, `audit/status_list.py`) → мониторинг (`services/monitoring.py`) → вебхуки (`services/webhooks.py`). Советник-модель (`advisory/llm.py`, `advisory/gate.py`) сбоку: его находки попадают в отчёт только справкой и вердикт не меняют (ADR-001).

## Входы и границы доверия

| Вход | Где | Граница сейчас |
|---|---|---|
| CLI | `cli.py` | локальный оператор, файлы с диска. `mandat demo` и `mandat eval` в защищённом режиме завершаются ошибкой |
| HTTP | `api/app.py`: `POST /v1/cases`, `GET /v1/cases/{id}`, `GET …/report.html`, `GET …/review`, `POST …/review/{action}`, `GET /v1/review/queue`, `POST /v1/events`, `GET /health`, `GET /readyz` | Bearer-токен, роли `operator`, `reviewer`, `auditor`, `admin` (`api/principals.py`), лимит частоты, тело до 8 МБ потоком, глубина JSON до 64. Профиль `demo` вне demo/dev/test — 403, по умолчанию `strict` |
| Библиотека | `services/verify.py::verify_case` | вызывающий код задаёт `ports`, `trusted_sources`, `now`; профиль по умолчанию берётся из режима (`services/env_policy.py`) |
| Файлы кейса | манифест, XML МЧД, выписки, устав | недоверенные. Отметки клиента об уставе и форме передоверия принимает только профиль demo вне защищённого режима |
| Снимки источников | выписка ЕГРЮЛ, снимок реестра МЧД, сведения о банкротстве в пакете | недоверенные, пока источник не входит в `trusted_sources`; снимок реестра без момента запроса вне demo — «не проверено» |
| Модель | `MANDAT_LLM_BASE_URL`, `MANDAT_LLM_ALLOWED_HOSTS` (по умолчанию `127.0.0.1,localhost`) | без переадресаций и прокси, ответ до 2 МБ, числовые поля проверяются схемой, текст документа отделён маркерами |
| Хранилище | `api/storage.py` (память, SQLite, Redis) | `MANDAT_API_STORE`; заявка на `case_id` условная: в памяти под блокировкой, в SQLite `INSERT OR IGNORE`, в Redis `SET NX` |
| Вебхуки | `services/webhooks.py` | HMAC-подпись, окно времени, хранилище повторов обязательно вне demo/dev/test |
| Ключи | на стенде `var/demo/keys/attestation_ed25519.pem` и `representative_hmac.key` | файлы создаёт только `mandat demo`, права 0600 сразу при создании; ключ HMAC не короче 32 байт. В `pilot` и `prod` ключ подписи — PEM с фразой или HSM, Vault Transit, AWS KMS (`MANDAT_SIGNER`) |

## Нарушители

| Нарушитель | Возможности | Цель |
|---|---|---|
| Клиент банка или его представитель | присылает пакет документов и манифест | получить «подтверждено» для лица без полномочий |
| Злоумышленник, захвативший учётную запись клиента | то же, плюс подменённая МЧД или выписка | провести операцию от имени компании |
| Внешний клиент API с токеном | любые запросы в пределах роли | выбрать слабый профиль, перегрузить сервис, прочитать чужие кейсы |
| Сотрудник банка (внутренний нарушитель) | доступ к разбору, журналу, файлам ключей на узле | принять кейс без оснований, исправить журнал, выпустить удостоверение |
| Поставщик модели или содержимое документа | ответ модели, текст внутри документа | внедрить инструкцию, протащить число или факт без цитаты |
| Отправитель вебхуков | запросы на `/v1/events` | подделать или повторить событие отмены |

| Сценарий | Мера | Тест | Остаточный риск |
|---|---|---|---|

| Отметить в манифесте «устав не ограничивает» | отметке верит только demo | `test_charter_mark_*` | записи согласования юриста нет |
| Отметить «передоверитель — юрлицо» | отметка не принимается ни в каком профиле, вид берётся из МЧД | `test_subdelegator_kind_*` | — |
| Пустой `СвНотУд` вместо нотариального удостоверения | нужны реквизиты, обязательные по XSD | `test_notarization_without_details_is_not_accepted` | с реестром нотариальных действий не сверяется |
| Повторить `СвДов` или `СвРосОрг` с другим значением | документ с повтором одиночного элемента не читается | `test_repeated_single_element_in_poa_is_not_read_silently` | — |
| Два документа с одним `id` | `id` непустой и уникальный | `test_intake_*` | неизвестные поля манифеста не отвергаются |

| Свежий снимок «действует» для давней операции или наоборот | снимок со временем запроса, срок свежести | `test_registry_*` | срок свежести — параметр банка |
| XML-бомба, внешние сущности | `defusedxml`, лимиты размера, глубины, числа элементов | `test_r_fmt_001_xml_bomb_rejected` | — |
| Глубокий JSON, огромное тело | предел глубины 64, тело до 8 МБ потоком | `test_api_body_*` | медленный клиент и память под нагрузкой не замерялись |
| Два одновременных решения по одной версии кейса | проверка и запись под одной блокировкой журнала; по HTTP роль разбирающего берётся из токена | `test_two_concurrent_decisions_on_one_version_write_one_record`, `test_operator_cannot_decide` | в библиотечном вызове роль по-прежнему передаёт вызывающий код |
| Два одновременных `POST` с одним `case_id` | условная заявка: один запрос получает отчёт, второй — 409 | `test_concurrent_create_with_same_case_id_does_not_overwrite` | журнал и хранилище остаются двумя системами ([границы](../../LIMITS.md#безопасность-и-защита-данных)) |
| Правка или обрезка журнала | хеш-цепочка, HMAC в защищённом режиме, файл-свидетель, корень Меркла; внешний якорь закрытых сегментов (`MANDAT_JOURNAL_ANCHOR`) | `tests/test_journal_transaction.py`, `test_merkle_anchor_catches_rewritten_journal` | без внешнего якоря замена журнала и ключа вместе не обнаруживается |
| Подбор ИНН по токену в удостоверении | HMAC на ключе издателя | `test_representative_inn_is_not_a_plain_hash` | правовое основание токена не согласовано |
| Удостоверение с чужим ключом, просроченное или из demo | `validate_attestation` | `tests/test_attestation_validation.py` | на стенде ключ подписи лежит файлом; в пилоте его держит HSM или KMS банка |
| Повтор или подделка вебхука | HMAC, окно времени, хранилище повторов | `tests/test_webhooks.py` | разные события с одинаковым телом неразличимы |
| Инструкция внутри документа для модели | маркеры данных, факт модели без дословной цитаты не засчитывается | `test_llm_and_webhook_*` | качество модели не оценивалось |

## Кто за что отвечает

| Мера | «Мандат» | Инфраструктура банка | Совместно |
|---|---|---|---|
| Проверка КЭП и сертификата | порт `SignaturePort` (по умолчанию `NotConnectedSignature`: «не проверено») | СКЗИ банка | подключение порта |
| Реестр МЧД, ЕГРЮЛ, ЕФРСБ | порты и снимки со временем запроса | доступ к источникам | договор и тестовая среда |
| Идентификация клиента (115-ФЗ), антифрод (161-ФЗ) | не реализует | процессы банка | вердикт «Мандата» — одна ось из четырёх |
| Защита ПДн (152-ФЗ) | псевдонимизация HMAC в логах и запросах к модели, случайные индексы статуса | классификация ИСПДн, меры по ПП № 1119 и приказам ФСТЭК | цели и основания обработки |
| Хранение ключей | файлы 0600 в demo; подписанты PKCS#11, Vault Transit и AWS KMS | KMS или HSM | выбор модуля и ротация ключа |
| Неизменяемость журнала | хеш-цепочка, корень Меркла, внешний якорь сегментов | приёмник якоря в контуре: TSA, Rekor, СЭД или SIEM | выбор приёмника и политика `MANDAT_JOURNAL_ANCHOR_POLICY=fail` |

## Корреляция и обезличивание

Номера МЧД, ИНН организации, `reportSha256`, `inputs` и токен представителя в удостоверении связывают записи об одном лице и одной операции. HMAC-токен не обезличивание: при одном ключе одинаковый ИНН даёт одинаковый токен. Индексы в списке статусов случайные и уникальные (`tests/test_status_privacy.py`), но сам список показывает, сколько удостоверений отозвано. Сведения об операции могут составлять банковскую тайну и без ФИО.
