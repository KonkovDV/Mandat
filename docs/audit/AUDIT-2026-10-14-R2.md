## Линзы экспертов

### 1. Юрист (ГК 182–189, 63-ФЗ, формат МЧД, 152-ФЗ)
- Основания прекращения доверенности по ст.188 п.1: подп.4 (прекращение или реорганизация юрлица) и подп.7 (банкротство) сверены с текстом статьи. Пробел R2-LAW-1 закрыт.
- Выделение и преобразование доверенность не прекращают (ст.188 п.1 подп.4). Поэтому для «reorganizing» вердикт NEEDS_REVIEW, а не REFUTES.
- Открыто:
  - XSD формата МЧД ФНС не проверяется (проверяется только наш JSON-срез);
  - нет проверки по реестру отзывов ФНС в реальном времени (только снимок);
  - правила — черновик, и это видно в карточке.

### 2. Банкир (онбординг и ДБО, 115-ФЗ, нагрузка операторов)
- Вердикт NEEDS_REVIEW направляет дело оператору и не отказывает автоматически, так что ложный отказ клиенту невозможен по конструкции.
- Цена ошибки ложится на очередь: каждый «reorganizing» добавляет ручную проверку.
- Пропускная способность на одной машине — около 140 RPS. Для ДБО этого с запасом хватает, SLA по задержке p95 < 1 с при 16 клиентах.
- Точки интеграции: ЕГРЮЛ/ФНС (снимок), АБС (через API), журнал для комплаенса по 115-ФЗ.
- Открыто: метрики очереди операторов, SLA-алерты.

### 3. ИБ (821-П, ГОСТ Р 57580.1-2017, ФСТЭК)
- Классы данных: ПДн представителей (152-ФЗ) и ключи подписи.
- Ключи: plaintext PEM запрещён в pilot/prod (RT-05). Есть шифрованный PEM, PKCS#11, Vault и KMS.
- Журнал: hash-chain + HMAC + witness-файл, подмена ловится (тесты).
- Сетевые защиты:
  - заголовки на всех ответах (R2-API-1);
  - лимит конкурентности, перегрузка даёт 429, p99 149 мс (R2-API-2);
  - CIS-лимиты контейнера (R2-CIS-1).
- Открыто:
  - СКЗИ с сертификатом ФСБ и ГОСТ-криптонабор (R2-CRYPTO-1);
  - внешний якорь журнала (ротация сегментов сделана в R2.1);
  - required checks / branch protection: включает владелец репозитория.

### 4. Антифрод (поддельная МЧД, устаревший снимок, replay, инсайдер)
- Поддельная подпись: Ed25519 Data Integrity, ключ берётся из `verificationMethod` и сверяется с keyring.
- Устаревший снимок: TTL claim и first_seen. Гонка S-3 покрыта тестами.
- Replay: повторный create с тем же id даёт 409.
- Подмена файлов дела на диске: S-4.
- Инсайдер-оператор: любое решение пишется в журнал с HMAC. Удаление строки или правка той же длины ловятся (тест на content hash).
- Открыто: разделение ролей «оператор / администратор ключа журнала» должно быть организационным.

### 5. Пользователь (HTML-карточка, WCAG 2.2 AA)
- Контраст всех цветов вердикта ≥ 4.5:1 (SC 1.4.3), проверено тестом.
- Таблицы получили заголовки столбцов и подписи (SC 1.3.1). Отметка «черновик» показана явно.
- Открыто: ручная проверка экранным диктором не проводилась.

### 6. Жюри хакатона (питч, демо из чистого клона, README)
- `run-demo.sh` из чистой копии проходит.
- Первый экран README и счётчики тестов обновлены по `evidence.json`.
- Слайды пересобираются через `make deck`; устаревшее число 585 заменено (если сборка прошла — см. коммит).

## Приоритеты
Раунд R2.1 закрыл R2-PERF-2, R2-API-3, R2-SC-1 и R2-EVID-1. Осталось:
1. Required status checks и branch protection — действие владельца репозитория.
2. R2-CRYPTO-1 — ГОСТ-криптонабор и СКЗИ; SoftHSM в CI.
3. R2-LOAD-1 — нагрузочный прогон RedisStore.
4. Внешний якорь журнала (публикация хеша закрытого сегмента вне машины): без него root на хосте может переписать сегменты и свидетель вместе с ключом.
5. `pip install --upgrade pip` в CI без закрепления версии (Low).
6. Юридическая валидация правил юристом банка; XSD МЧД ФНС.
