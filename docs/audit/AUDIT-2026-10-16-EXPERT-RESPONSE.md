# Ответ на статический разбор 16.10.2026

Внешний разбор читал документацию и исходники и сам пишет, что набор тестов не запускался. Это не независимый прогон. Оценки из того текста в README и в реестр утверждений не переносятся.

Корпус, границы ошибок и различие фазза входных сценариев с mutmut кода разбор прочитал так же, как [реестр утверждений](../../CLAIMS_REGISTRY.md): ноль ложных «подтверждено» на синтетике не есть риск на документах банка. 8 814 мутаций в README — изменения тестовых документов, не mutmut `checks.py`.

## Что закрыто кодом

| Замечание | Что сделано |
|---|---|
| Обязательный устав с найденным фрагментом всё ещё мог вести к «подтверждено» | R-CHR-002: для операции, где устав обязателен, найденные положения без отметки demo «ограничений нет» дают «на разбор». Отметка demo и операция без обязательного устава ведут себя как раньше |
| Соседние передоверия в один день не имели политики | Два разных документа (разный sha256) от одной МЧД в один день — «на разбор» тем же R-SUB-009. Одинаковый документ повтором не считается. Нового идентификатора правила нет |
| `check_status` без `now` возвращал «действует» | В pilot, prod и любом защищённом режиме без `now` состояние — «свежесть не проверена». Отзыв и приостановка сообщаются и без `now`. На стенде без `now` прежнее поведение |
| Упавший писатель оставлял lock журнала | В lock пишется pid. Снятие только если процесс точно мёртв. По возрасту файла lock не снимается |
| Поздняя выписка «отменена» без даты события читалась как опровержение на дату операции | R-REG-001: снимок после даты операции без даты события — «на разбор»; R-SUB-006 в этом случае не гасит передоверие. Снимок без момента запроса по-прежнему опровергает. Ст. 189 целиком этим не закрыта |
| Неизвестный признак совместности у листа с одним представителем молчал | R-JNT-001: нет ПрСовмПолн — «на разбор» и при одном представителе |
| Код классификатора без даты начала считался действующим | R-COV-002: нет даты начала — «на разбор», в политику Cedar код не попадает. Нет даты исключения по-прежнему значит, что код не отозван |

Тесты: `tests/test_expert_followup_2026_10_16.py`. Полный mutmut по-прежнему ручной и не входит в CI ([MUTATION](../testing/MUTATION.md)).

## Что этим не закрыто

- Все 39 правил остаются `draft`. Письменного утверждения юристом банка нет. Карточка нормы на каждое правило — следующий этап, не сделанная работа.
- Реестр МЧД, ЕГРЮЛ, ЕФРСБ и проверка КЭП на стенде — порты. Без СКЗИ банка подпись остаётся непроверенной, строгий профиль не подтверждает.
- Официальной схемы оператора реестра в репозитории нет. Совпавшие копии XSD её не заменяют.
- Журнал и хранилище не образуют одну транзакцию (M-10, [LIMITS](../../LIMITS.md)). Повтор без ключа идемпотентности после сбоя может получить 409.
- Корень Меркла сам никуда не публикуется. Внешний якорь — свойство контура банка, не этого репозитория.
- Реестр статусов по-прежнему только POSIX (`fcntl`).
- Одиночная фамилия вне словаря и без русского суффикса без подсказки о человеке («В протоколе назван Шор») в модель может уйти как есть. «по заявлению Шор» маскируется. Перед моделью на документах банка этот путь нужно гонять отдельно.
- План по Федеральному закону № 315-ФЗ и дате 1 сентября 2027 года уже лежит в [MIGRATION-315-FZ-R-FMT-001](../research/MIGRATION-315-FZ-R-FMT-001.md). Это обязательство сверить правило, не выполненная миграция.
- Шесть недель в тени и 50–100 пакетов в [PILOT](../PILOT.md) — план. Протокол не подписан, прогон не проводился.
- Оценка по Положению Банка России № 851-П, Положению № 821-П и ГОСТ Р 57580.1 относится к развёртыванию в банке. Репозиторий её не даёт. То же про 152-ФЗ и 115-ФЗ: маскировка и разбор полномочий не заменяют меры оператора и идентификацию банка.
