# Предметная модель и форматы входа

Сущности, с которыми работает «Мандат», и форматы входных файлов: манифест кейса, ЕГРЮЛ, граф полномочий. Формат МЧД разобран отдельно в [FORMAT_NOTES](FORMAT_NOTES.md).

## Сущности

| Сущность | Поля | Откуда |
|---|---|---|
| `Organization` | ИНН, ОГРН, КПП, наименование | заявка, МЧД, ЕГРЮЛ |
| `Person` | ФИО, ИНН, СНИЛС, должность | заявка, МЧД, ЕГРЮЛ |
| `PowerOfAttorney` | номер (GUID), даты выдачи и окончания, признак передоверия (`ПрПередов`), утрата полномочий при передоверии (`ПрУтрПолн`), совместные полномочия (`ПрСовмПолн`; отсутствие признака — не «индивидуально», R-JNT-001), признак передоверия безотзывной доверенности, доверитель, подписант (ЕИО), представители, полномочия, номера родительской и первоначальной МЧД; срок по закону, если не указан (`effective_until`, п. 1 ст. 186 ГК РФ) | МЧД XML |
| `Authority` | машиночитаемое (код, мнемоника, наименование) или текстовое | МЧД XML |
| `ExecutiveRecord` | руководитель, ГРН, дата записи, период действия, отметка о недостоверности | ЕГРЮЛ |
| `EgrulSnapshot` | организация, полное наименование, статус, история руководителей | ЕГРЮЛ |
| `ClassifierEntry` | код полномочия, мнемоника, наименование, даты начала действия и исключения | снимок классификатора (ЕСНСИ) |
| `Operation` | код операции, дата, сумма | заявка |
| `Finding` | правило, группа, эффект, вывод, норма, ссылки, следующий шаг, подразделение | правила |
| `EvidenceRef` | документ, его sha256, локатор (XPath, путь JSON, диапазон текста, ключ реестра), цитата | приём документов |

Два человека считаются одним лицом только при совпадении ИНН или СНИЛС. Совпадение ФИО доказательством не считается: такой случай уходит на разбор.

## Манифест кейса `case.json`

```json
{
  "case_id": "01_ok",
  "organization": {"inn": "…", "ogrn": "…", "name": "ООО «…»"},
  "requester": {"full_name": "…", "inn": "…", "snils": "…"},
  "operation": {"code": "PAYMENT_SIGN", "date": "2026-10-20", "amount_rub": 480000},
  "documents": [
    {"id": "poa-root", "kind": "emchd_xml", "path": "poa-root.xml"},
    {"id": "charter", "kind": "charter_text", "path": "charter.txt"},
    {"id": "egrul", "kind": "egrul_json", "path": "egrul.json"}
  ],
  "registry": {"<номер МЧД>": "active"}
}
```

Виды документов: `emchd_xml`, `egrul_json`, `charter_text`, `paper_poa_text`. В API вместо `path` передаётся `content` (строка или JSON-объект). Пути не могут выходить за каталог кейса.

`registry` — статусы для заглушки реестра: `active`, `revoked`, `expired`, `not_found`, `unavailable`. Нет записи — реестр считается недоступным.

## ЕГРЮЛ: внутренний нормализованный формат

```json
{
  "inn": "…", "ogrn": "…", "kpp": "…", "name": "ООО «…»",
  "full_name": "ОБЩЕСТВО С ОГРАНИЧЕННОЙ ОТВЕТСТВЕННОСТЬЮ «…»",
  "status": "active | reorganizing | in_liquidation | liquidated | terminated | unknown",
  "extracted_at": "2026-10-19",
  "executives": [
    {"full_name": "…", "inn": "…", "position": "Генеральный директор", "grn": "…",
     "record_date": "2024-05-01", "valid_from": "2024-05-01", "valid_to": null, "unreliable": false}
  ]
}
```

Это не выписка ФНС: адаптер банка в пилоте приводит ответ СМЭВ или внутреннего сервиса к этой форме. История руководителей нужна, чтобы проверить руководителя на дату выдачи МЧД и на дату операции.

## Граф полномочий

```
Организация ──(ЕИО по ЕГРЮЛ на дату выдачи)──► Подписант корневой МЧД
     └─ МЧД-1 (коды, срок, признак передоверия) ──► Представитель-1
            └─ МЧД-2 (передоверие, не шире, не дольше) ──► Представитель-2 = заявитель
```

На каждом ребре проверяются срок на дату операции, статус в реестре, право передоверия (однократное используется один раз), сужение полномочий, срок передоверия и единый доверитель. Отмена или истечение основной МЧД обрывает все производные (п. 3 ст. 188 ГК РФ). Если передоверие оформлено с утратой полномочий (`ПрУтрПолн = 2`), передоверитель больше не вправе действовать по своей МЧД. Смена руководителя после выдачи МЧД доверенность не прекращает ([ADR-002](adr/ADR-002-director-change.md)).
