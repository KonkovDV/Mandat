# ADR-009. Утверждение правила — подписанная запись юриста, а не строка в файле

Решение: правило считается утверждённым только по действующей записи в файле утверждений, подписанной ключом из связки утверждающих. Строка `status: approved` в `rules.json` статус не меняет.

**Контекст.** До 17.11.2026 статус правила был строкой в `src/mandat/data/rules.json`: кто поменял `draft` на `approved`, тот и «утвердил». Профиль `strict` доверяет только утверждённым правилам, поэтому правка одной строки снимала главную защиту от ложного «да». Подход Rules as Code (OECD OPSI, 2020) требует, чтобы у машинной нормы были ответственный и редакция.

**Решение** (`src/mandat/rules/approvals.py`):
- Запись: пакет, `rule_id`, хеш утверждаемого текста правила (`id`, `check`, `title`, `norm_ref`, `effects`), решение `approve`, редакция нормы и дата сверки, роль утверждающего без ФИО, дата подписи, последний день действия, идентификатор ключа и подпись Ed25519 по канонической записи RFC 8785.
- Запись действует, если подпись проверяется ключом из связки (`MANDAT_APPROVAL_KEYS`, формат как у [связки ключей](../KEYS.md#идентификатор-ключа-и-связка)), ключ действовал в момент подписи, хеш совпадает с текущим текстом правила, дата подписи не в будущем, срок не истёк и не длиннее года.
- Правка утверждаемого текста после подписи снимает утверждение. Параметры банка, подразделение и следующий шаг — операционные поля: их правка подписи не требует.
- Для правил, которые читают каталог операций (R-EIO-002, R-COV-001, R-COV-002, R-CHR-002), утверждаемый текст включает и хеш каталога `operations.json`: от него зависит, какие коды покрывают операцию, нужен ли устав и высок ли риск. Правка каталога снимает их утверждение. Список правил тест собирает из кода, а не из документа.
- Связка утверждающих — якорь доверия. В `pilot`, `prod` и любом защищённом режиме файл связки, доступный на запись сервису, группе или всем, не читается.
- Статусы выводятся в любом профиле. Правило `retired` запись не возвращает. Нечитаемый файл утверждений не роняет проверку: все правила остаются черновиками, причина — в предупреждениях отчёта.
- В репозитории файл утверждений пуст, все 39 правил — `draft`.

**Границы.**
- Подпись покрывает текст правила, а не код проверки. Код держат тесты из поля `tests` и запрет менять правила без теста.
- Подпись защищает каждую запись, но не полноту набора. Удалить запись — безопасная сторона: правило становится черновиком. Вернуть удалённую запись можно, пока не истёк её срок: поэтому срок не длиннее года, а отозвать все записи юриста разом — значит пометить его ключ `revoked`.
- На стенде запись подписывает ключ Ed25519 (`mandat approvals-sign`). В банке подпись — КЭП юриста через СКЗИ; для этого нужен порт проверки ГОСТ-подписи, как и для МЧД.

**Альтернативы.** Подпись всего файла `rules.json` одним юристом: проще, но любая правка одного правила снимает утверждение со всех, а частичное утверждение невозможно. Утверждение в СЭД банка со ссылкой в `rules.json`: движок не может проверить ссылку сам, и строка снова становится доверенной.

**Проверка.** `tests/test_b1_rule_approvals.py`: подделанный `approved` во всех правилах без записей не даёт «подтверждено» в `strict`, с записями на тестовом ключе — даёт; чужой, отозванный и выведенный ключ, истёкший срок, подпись в будущем, правка `norm_ref`, `title`, `check` или `effects` после подписи и правка самой записи — правило остаётся черновиком.
