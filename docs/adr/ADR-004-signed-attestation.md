# ADR-004. Результат проверки — подписанное удостоверение

**Контекст.** Результат проверки нужен другим системам банка (ДБО, антифрод, аудит), и проверять его хочется без доступа к базе «Мандата». Мировой ориентир — роли сотрудников как проверяемые удостоверения (GLEIF vLEI, ISO 17442-3).

**Решение.** На каждый отчёт выпускается JSON в модели W3C Verifiable Credentials 2.0 с доказательством Data Integrity в духе `eddsa-jcs-2022`: хеш конфигурации доказательства и хеш документа, подпись Ed25519, значение в base58btc. В удостоверении — ИНН организации, токен представителя (HMAC-SHA256 на ключе издателя; простой хеш 12-значного ИНН подбирается перебором), операция, вердикт, профиль, хеш набора правил, хеш отчёта и хеши входных документов. ФИО и паспортных данных нет.

**Проверка.** `test_attestation_sign_verify_and_tamper`, `tests/test_attestation_validation.py`, `tests/test_jcs.py`, команда `mandat attest-verify`. Каноническая запись — RFC 8785 (`audit/jcs.py`), проверена на примерах из текста RFC; совместимость с внешними верификаторами VC не проверялась. Подпись верна ≠ удостоверение принимается: `validate_attestation` проверяет доверенный ключ, издателя, назначение, криптонабор, срок `validUntil`, профиль (demo в защищённом режиме не принимается) и статус.

**Ограничения.** Совместимость с внешними верификаторами VC не проверялась. Издатель — `did:web:mandat.example`, в пилоте — ключ и идентификатор банка. Идея перенесена из fsp-talent (ADR-0007).
