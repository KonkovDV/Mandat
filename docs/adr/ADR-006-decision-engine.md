# ADR-006. Своё ядро решений, Cedar — для независимой проверки

**Контекст.** Мировой уровень авторизации в 2026 году — это Cedar (CNCF Sandbox с 08.10.2025, спецификация проверена в Lean), OpenFGA (модель Zanzibar, CNCF Incubation с 28.10.2025), OPA/Rego. Все они отвечают на вопрос «разрешено ли сейчас». «Мандату» нужно другое:

- четыре вердикта, включая «на разбор» и «недостаточно данных»;
- вычисление на дату операции по истории ЕГРЮЛ и реестра;
- доказательство к каждому выводу (XPath, ГРН, цитата, норма).

**Решение.**
- Ядро остаётся своим: граф полномочий, правила-данные, свёртка без ложного «да» (ADR-001, ADR-003).
- Ядро правил передоверия (покрытие, срок, реестр, право передоверия, сужение, срок передоверия, каскад) экспортируется в политики Cedar: `rules/cedar_export.py`, `policies/cedar/`.
- `tests/test_cedar.py` проверяет политики валидатором Cedar по схеме и сравнивает решения Cedar с вердиктами «Мандата» на всех 384 двухзвенных цепочках (8 × 8 наборов кодов × 3 значения `ПрПередов` × 2 варианта срока).
- `tests/test_properties.py` на том же переборе проверяет закрытую формулу: «подтверждено» тогда и только тогда, когда передоверие разрешено, не шире и не дольше родительской МЧД и покрывает операцию.

**Почему не OpenFGA.** Нет истории на дату и нет доказательной базы, а для пилота это лишний сервер.

**Последствия.** Две независимые реализации одного свойства: расхождение ловит ошибку в любой из них. Следующий шаг (P2) — доказать свойство для всех входов, а не для перебора, через символьный анализ Cedar.
