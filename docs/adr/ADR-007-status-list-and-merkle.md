# ADR-007. Статус удостоверений и доказуемый журнал

**Контекст.** Удостоверение о проверке полномочия живёт дольше самой проверки: МЧД могут отменить, руководитель может смениться, может начаться захват компании. Проверяющая сторона (ДБО, антифрод, аудит) должна видеть актуальный статус, не обращаясь к базе «Мандата». Аудитору нужно доказать, что конкретное решение есть в журнале, и не отдавать при этом весь журнал.

**Решение.**
- **W3C Bitstring Status List v1.0** (Рекомендация W3C с 15.05.2025). В каждом удостоверении `credentialStatus` указывает номер бита в двух списках — `revocation` и `suspension`. Списки — подписанные удостоверения `BitstringStatusListCredential`: 131 072 бит, GZIP, multibase base64url. Номера выдаются случайно, чтобы по номеру нельзя было судить о порядке выдачи (`audit/status_list.py`).
- Мониторинг выставляет биты по тревогам. Отмена или истечение МЧД — `revocation` для удостоверений, в цепочке которых эта МЧД. Признаки захвата — `suspension` для всех неопровергнутых удостоверений организации. Команды: `mandat monitor … --status-dir`, `mandat attest-verify … --status-dir`.
- **Дерево Меркла над журналом** по RFC 6962 / RFC 9162 (`audit/merkle.py`): `mandat journal-verify` печатает корень, `mandat journal-proof --seq N` выдаёт доказательство включения записи из log2(n) хешей. Хеш-цепочка с HMAC остаётся.

**Проверка.** `test_bitstring_encoding_follows_w3c_layout`, `test_status_list_revocation_is_signed_and_checked`, `test_monitor_revokes_and_suspends_attestations`, `test_merkle_inclusion_proofs_for_every_size`, `test_journal_proof_cli`.

**Ограничения.** Подпись — Ed25519, не ГОСТ. Совместимость с внешними верификаторами VC не проверялась. Корень дерева пока никуда не публикуется: внешний якорь — задача пилота.
