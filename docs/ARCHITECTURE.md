# Архитектура

## Слои

| Слой | Модули | Правило зависимостей |
|---|---|---|
| Домен | `domain/model.py`, `identifiers.py`, `graph.py`, `verdict.py` | ничего не импортирует из инфраструктуры |
| Приём | `intake/xml_safety.py`, `emchd.py`, `formats.py`, `egrul.py`, `charter.py`, `case_loader.py` | ошибки разбора превращаются в `intake_errors`, а не в исключения; форматы МЧД — через адаптеры (ADR-008) |
| Правила | `rules/pack.py`, `rules/checks.py`, `rules/classifier.py`, `data/rules.json`, `data/authority_classifier.json` | метаданные и параметры в JSON, логика в коде; состав сверяется тестом |
| Независимая проверка | `rules/cedar_export.py`, `policies/cedar/` | ядро передоверия в Cedar, дифференциальный тест (ADR-006) |
| Порты | `ports.py` | реестр МЧД, проверка подписи; в MVP заглушки |
| Сервисы | `services/verify.py`, `next_steps.py`, `rights.py`, `monitoring.py` | оркестрация, без знания о форматах |
| Аудит | `audit/journal.py`, `audit/merkle.py`, `audit/attestation.py`, `audit/status_list.py` | append-only, доказательство включения, удостоверения со статусом отзыва — всё проверяемо без базы (ADR-007) |
| Советник | `advisory/gate.py`, `llm.py`, `copilot.py` | не влияет на вердикт |
| Интерфейсы | `cli.py`, `api/app.py`, `report/html.py` | тонкие обёртки над сервисами |

## Поток проверки

1. `case_loader` читает манифест, считает sha256 каждого документа, разбирает МЧД (`defusedxml` + лимиты), ЕГРЮЛ (нормализованный JSON), устав и бумажные доверенности как текст. Сбой разбора — запись в `intake_errors`.
2. `graph.build_chain` строит путь: заявитель — действующий руководитель по ЕГРЮЛ (`eio_direct`), представитель по цепочке МЧД (`poa`), только бумажная доверенность (`paper`) или представитель не найден (`none`). Цепочка идёт от листа к корню по `parent_number`, с защитой от циклов.
3. Каждое правило пакета возвращает находки. У находки есть правило, группа, юридический эффект (`refutes`, `needs_review`, `not_verified`, `supports`, `info`), норма, ссылки на источник и, для проблемных, следующий шаг и подразделение. Находку без ссылки на источник создать нельзя.
4. `verdict.fold` сворачивает находки с учётом профиля:
   - опровержение → ОПРОВЕРГНУТО;
   - обязательная группа «не проверено» или «нет данных» → НЕДОСТАТОЧНО ДАННЫХ;
   - разбор → НА РАЗБОР;
   - все обязательные группы с подтверждением → ПОДТВЕРЖДЕНО.

   В профиле `strict` опровержение по правилу без утверждения юристом понижается до разбора, а подпись обязательна. В `demo` подпись честно помечена как невыполненная.
5. `next_steps` группирует проблемные находки в действия для клиента и сотрудника, `route` ставит приоритет и SLA (заглушки до калибровки), `rights` готовит рекомендацию роли в теневом режиме.
6. Отчёт получает `reproducibility_hash` — хеш всего, кроме времени: одинаковый вход даёт одинаковый хеш. В отчёте есть плашка «Режим стенда»: что в этой проверке заглушка. CLI пишет запись в журнал и выпускает подписанное удостоверение с номером в списках статусов.
7. Мониторинг по событиям ЕГРЮЛ и реестра находит затронутые права и меняет статус удостоверений: «отозвано» при отмене или истечении МЧД (вместе со всей цепочкой передоверия), «приостановлено» при признаках захвата.

## Почему так

- **Неизвестное не становится «да»** — главный риск банка в этой задаче: пропущенный дефект полномочий дороже лишней проверки.
- **Правила — данные.** Норма, статус и текст следующего шага правятся в `data/rules.json`; теги формата МЧД — в `data/emchd_003_mapping.json`; коды полномочий для операций — в `data/operations.json`. Новая операция или замена кодов классификатора не требует кода; новое правило — требует, и тест не даст забыть реализацию или тест.
- **Порты вместо интеграций.** В пилоте заглушки реестра и подписи меняются на адаптеры банка без изменения ядра.
- **Ядро без зависимостей от сети.** Две зависимости: `defusedxml` и `cryptography`. FastAPI — отдельный extra.

## Дальше

Хранилище кейсов (PostgreSQL в контуре банка, таблицы с датами действия для истории «на дату»), очередь исключений с назначением сотрудников, адаптер ЕГРЮЛ (СМЭВ или внутренний сервис), адаптер реестра МЧД, проверка КЭП через СКЗИ банка, OIDC банка вместо статического токена, публикация корня журнала во внешнем якоре, символьное доказательство свойства передоверия на Cedar. Сравнение с мировым уровнем — `docs/SOTA.md`.
