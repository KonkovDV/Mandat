# Архитектура

Как устроен код «Мандата» и как кейс проходит путь от пакета документов до вердикта, журнала и удостоверения. Главный принцип: неизвестное не превращается в «да». Ядро работает без сети, а внешние системы подключаются через порты.

## Слои

| Слой | Модули | Правило |
|---|---|---|
| Домен | `domain/model.py`, `identifiers.py`, `graph.py`, `verdict.py` | не импортирует инфраструктуру |
| Приём | `intake/xml_safety.py`, `emchd.py`, `formats.py`, `egrul.py`, `charter.py`, `case_loader.py` | ошибка разбора попадает в `intake_errors`, а не роняет проверку; форматы МЧД — адаптеры ([ADR-008](adr/ADR-008-formats-and-classifier.md)) |
| Правила | `rules/pack.py`, `checks.py`, `classifier.py`, `data/*.json` | метаданные в JSON, логика в коде ([ADR-003](adr/ADR-003-rules-as-data.md)) |
| Перекрёстная проверка | `rules/cedar_export.py`, `policies/cedar/` | передоверие на Cedar ([ADR-006](adr/ADR-006-decision-engine.md)) |
| Порты | `ports.py` | реестр МЧД (запрос по номеру, ИНН доверителя и ИНН представителя, как в реестре ФНС с 01.03.2026), подпись, банкротство; в MVP заглушки |
| Контракт API | `docs/api/openapi.json` | фиксируется `scripts/export_openapi.py`; тест сверяет его с приложением и проверяет, что каждый маршрут, кроме `/health`, требует токен |
| Контракт манифеста кейса | `docs/api/case-manifest.schema.json` | JSON Schema 2020-12; `tests/test_r11_manifest_schema.py` проверяет, что схема и `intake/case_loader.py` принимают и отвергают одно и то же. Неизвестные ключи верхнего уровня загрузчик пропускает, схема — нет |
| Сервисы | `services/verify.py`, `next_steps.py`, `rights.py`, `monitoring.py` | собирают проверку, о форматах не знают |
| Аудит | `audit/journal.py`, `merkle.py`, `attestation.py`, `status_list.py` | всё проверяется без базы ([ADR-007](adr/ADR-007-status-list-and-merkle.md)) |
| Советник | `advisory/gate.py`, `llm.py`, `explainer.py` | на вердикт не влияет ([ADR-001](adr/ADR-001-verdict-ownership.md)) |
| Интерфейсы | `cli.py`, `api/app.py`, `report/html.py` | тонкие обёртки над сервисами |

## Путь кейса

1. `case_loader` читает манифест, считает sha256 каждого документа и разбирает МЧД (`defusedxml` с лимитами), ЕГРЮЛ (JSON), устав и бумажные доверенности (текст).
2. `graph.build_chain` определяет, кто заявитель: руководитель по ЕГРЮЛ (`eio_direct`), представитель по цепочке МЧД (`poa`), представитель только по бумажной доверенности (`paper`) или никто (`none`). Цепочка строится от листа к корню, циклы отсекаются.
3. Каждое правило возвращает находки. У находки есть эффект (`refutes`, `needs_review`, `not_verified`, `supports`, `info`), норма и ссылка на источник; без ссылки находку создать нельзя.
4. `verdict.fold` сворачивает находки: опровержение → ОПРОВЕРГНУТО; обязательная группа не проверена → НЕДОСТАТОЧНО ДАННЫХ; повод для разбора → НА РАЗБОР; все обязательные группы подтверждены → ПОДТВЕРЖДЕНО. Порядок и профили — в [RULES](RULES.md).
5. `next_steps` превращает проблемные находки в действия для клиента и сотрудника, `route` ставит приоритет и срок (P1 — 4 ч, P2 — 24 ч, P3 — 72 ч; заглушки до калибровки), `rights` готовит рекомендацию роли. В отчёт попадает сильнейшее возражение. У «подтверждено» это сигнал из `SIGNAL_RULES` (например, смена руководителя), иначе находка того же рода, что и вердикт; снятая профилем проверка — только если ничего другого нет.
6. Отчёт получает `reproducibility_hash`: одинаковый вход даёт одинаковый хеш. Плашка «Режим стенда» перечисляет заглушки. CLI пишет запись в журнал и выпускает подписанное удостоверение.
7. Мониторинг по событиям ЕГРЮЛ и реестра отзывает удостоверения при отмене или истечении МЧД (со всей цепочкой передоверия) и приостанавливает их при признаках захвата.

Профиль `strict` пока почти ничего не решает сам: без подключённого СКЗИ на корпусе 276 из 294 кейсов получают «недостаточно данных», 18 — «на разбор». Это ожидаемо, цифры — в `evidence.json`.

## Почему так

- Пропущенный дефект полномочий дороже лишней ручной проверки, поэтому недоступный источник даёт «недостаточно данных», а не «да».
- Норма, статус и текст шага правятся в `data/rules.json`, теги формата — в `data/emchd_003_mapping.json`, коды операций — в `data/operations.json`. Новая операция кода не требует, новое правило требует, и тест не даст забыть реализацию.
- В пилоте заглушки реестра и подписи меняются на адаптеры банка без правки ядра.
- У ядра две зависимости, `defusedxml` и `cryptography`. FastAPI ставится отдельно.

## Чего нет

Хранилища кейсов с историей на дату, очереди исключений, адаптеров ЕГРЮЛ и реестра МЧД, проверки КЭП через СКЗИ, OIDC, внешнего якоря для корня журнала. Полный список — [LIMITS](../LIMITS.md), план — [ROADMAP](ROADMAP.md).
