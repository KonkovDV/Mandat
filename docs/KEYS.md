# Модель ключей

Какие ключи нужны Мандату, как их создавать, где хранить, как менять и как после смены проверять старые журналы и удостоверения. Для демо ключи создаются сами в `var/demo/keys/`; в пилоте и проде так делать нельзя.

## Перечень

| Ключ | Где задаётся | Назначение | Требование при `MANDAT_ENV=pilot/prod` |
|---|---|---|---|
| HMAC журнала | `MANDAT_JOURNAL_KEY` | подпись записей и файла-свидетеля журнала решений | обязателен, не короче 32 байт |
| Псевдонимизация ПДн | `MANDAT_PII_KEY` | HMAC-токены ИНН/СНИЛС в логах и запросах к модели | обязателен, не короче 32 байт |
| Токен стенда | `MANDAT_API_TOKEN` | общий токен роли `admin`, только без `MANDAT_API_USERS` | не короче 32 байт; в пилоте лучше `MANDAT_API_USERS` |
| Токены пользователей | `MANDAT_API_USERS` | хеши SHA-256 токенов с ролями | токены выдаёт `mandat api-user` |
| Подпись удостоверений | PEM Ed25519 (`--key`, по умолчанию `keys/attestation_ed25519.pem`) | подпись удостоверений и списка статусов | файл 0600 или ключ в HSM через адаптер банка |
| HMAC представителя | `keys/representative_hmac.key` | токен представителя в удостоверении | не короче 32 байт |
| Секрет вебхуков | `MANDAT_WEBHOOK_SECRET` | Standard Webhooks, `whsec_` 24–64 байт | обязателен формат `whsec_` |

С 14.10.2026 `mandat serve` проверяет ключ журнала, ключ ПДн и длину токена стенда при старте и в защищённом режиме не запускается без них (код выхода 2). Раньше нехватка ключа обнаруживалась только на первой записи.

## Создание

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"   # MANDAT_JOURNAL_KEY, MANDAT_PII_KEY, MANDAT_API_TOKEN
mandat webhook-secret                                          # MANDAT_WEBHOOK_SECRET
mandat api-user <имя> <роль>                                   # строка для MANDAT_API_USERS
```

Ключ создаётся на машине, где он будет храниться, и не проходит через почту, чаты, тикеты и git. `.env` в репозиторий не кладётся.

## Хранение

1. **Пилот и прод: KMS или HSM банка.** Секреты HMAC выдаются процессу как переменные окружения из хранилища секретов (Vault, KMS-оператор Kubernetes, systemd `LoadCredential`). Ключ Ed25519 для удостоверений должен жить в HSM; Мандат сейчас читает только PEM-файл, поэтому адаптер подписи через HSM — задача интеграции (открыто).
2. **Стенд: переменные окружения или файл 0600** под непривилегированным пользователем, каталог `var/` не публикуется.
3. Ключи разных контуров (стенд, пилот, прод) не совпадают.

## Ротация

Плановая смена — не реже раза в год и сразу при подозрении на утечку или уходе сотрудника с доступом.

| Ключ | Порядок | Проверка старого |
|---|---|---|
| `MANDAT_JOURNAL_KEY` | закрыть текущий журнал, сохранить его хеш как внешний якорь (SECURITY.md), начать новый файл журнала с новым ключом | старый ключ переводится в архив только для чтения; `mandat journal-verify` старого файла запускается со старым ключом |
| `MANDAT_PII_KEY` | заменить ключ; токены до и после смены не сопоставляются — это ожидаемо | старые токены сверяются только старым ключом из архива |
| Ed25519 удостоверений | выпустить новую пару, опубликовать новый открытый ключ рядом со старым, переключить выпуск | проверка принимает список доверенных ключей (`validate_attestation(cred, [новый, старый])`); старый ключ убирается из списка, когда истёк срок принятия всех выданных им удостоверений (30 дней) |
| `MANDAT_WEBHOOK_SECRET` | новый и старый через пробел, новый первым; через окно доставки убрать старый | получатель принимает любую из подписей |
| Токены API | выдать новый через `mandat api-user`, удалить старую запись из `MANDAT_API_USERS`, перезапустить | — |

При компрометации ключа подписи удостоверений все выданные им удостоверения отзываются через список статусов, а старый открытый ключ сразу удаляется из доверенных.

## Что открыто

- Подпись Ed25519 через HSM (PKCS#11) без PEM-файла на диске.
- Автоматическая ротация ключа журнала с цепочкой «последняя запись старого журнала → первая нового».
- Решение банка о сроке хранения архивных ключей.
