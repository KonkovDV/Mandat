# Защита данных

Какие персональные данные обрабатывает «Мандат», что для их защиты уже есть в коде и что нужно к пилоту. Это проектные решения, а не оценка соответствия закону: её дают ИБ и юристы банка.

Данные: ФИО, ИНН, СНИЛС и должность представителей и руководителей. Разработка и демо идут только на синтетике (`eval/synth.py`, `examples/`).

## В коде

| Мера | Где |
|---|---|
| Ядро не делает сетевых запросов | `intake`, `rules`, `services` |
| Модель выключена по умолчанию и ходит только на хосты из `MANDAT_LLM_ALLOWED_HOSTS` | `advisory/llm.py` |
| В модель уходят только строки устава о полномочиях (`MODEL_KEYWORDS`); остальной текст документа модель не видит | `advisory/llm.py` (`minimize`) |
| ФИО людей из данных кейса (руководители по ЕГРЮЛ, представители и подписант МЧД, заявитель) заменяются меткой роли `[ДИРЕКТОР]`, `[ПРЕДСТАВИТЕЛЬ]`, `[ПОДПИСАНТ]` во всех падежах, в женской форме и с инициалами | `privacy/names.py` |
| В модель уходит только `RedactedMessages` из `llm.case_charter_messages`; сетевой вызов модели есть только в `advisory/llm.py` (проверка AST в CI) | `tests/test_llm_chokepoint.py` |
| Дата рождения и адрес человека вырезаются перед отправкой в модель: метка `[ДАТА_РОЖДЕНИЯ]` или `[АДРЕС]` без токена, сопоставить их между документами нельзя. Адрес юридического лица («место нахождения», «юридический адрес», «адрес общества») публичен и остаётся | `privacy/pii.py` (`redact`) |
| ИНН, СНИЛС, паспорт, телефон и почта псевдонимизируются HMAC перед отправкой в модель (ключ `MANDAT_PII_KEY`; в `pilot` и `prod` без него псевдонимизация отказывает, ключ разработки только для стенда). Паспорт со словом «номер» между серией и номером тоже («45 06 номер 123456», «паспорт 4506 номер 123456»). «2024 номер 123456» — номер договора, не паспорт. СНИЛС с точками («112.233.445.95», «112.233.445 95») перед моделью псевдонимизируется по тем же цифрам; проверка в движке точки по-прежнему не принимает. «112.233.445.96» с неверной суммой не СНИЛС. Пробелы между группами («112 233 445 95») тоже псевдонимизируются; «112 233 445 96» не СНИЛС. Телефон с точками («8.903.123.45.67», «+7.903.123.45.67») тоже псевдонимизируется. «8.100.000 рублей» — сумма, не телефон | `privacy/pii.py` |
| В удостоверении нет ФИО, представитель записан HMAC-токеном от ИНН | `audit/attestation.py` |
| Номера в списках статусов случайные | `audit/status_list.py` |
| Доказательство из журнала раскрывает одну запись | `audit/merkle.py` |
| Паспорт для проверки не нужен: представитель сверяется по СНИЛС или ИНН (Приказ Минцифры № 1001) | R-ID-003 |
| API закрыт без токена, `no-store`, CSP на HTML-отчёте | `api/app.py` |
| Журнал обнаруживает правку записей (хеш-цепочка, HMAC, свидетель), но не мешает ей | `audit/journal.py` |

Защита XML и путей — в [SECURITY](../SECURITY.md).

## Псевдонимизация — не обезличивание

Обезличивание по 152-ФЗ (ст. 3, п. 9) — это когда без дополнительной информации нельзя определить, кому
принадлежат данные. Здесь этого нет: токен HMAC по ключу сопоставляется с ИНН, а текст, ушедший в модель,
остаётся персональными данными. Поэтому модель — только в контуре банка, а ключ — в хранилище секретов.

Что не распознаётся и уходит в модель как есть, если стоит в строке о полномочиях:

- **слово с заглавной сразу после подсказки о человеке** («заявлению», «гражданина», «фамилии», «господина»,
  «г-н», «г-жа») заменяется меткой `[ФИО]`, даже если фамилии нет в словаре и у неё нет русского суффикса.
  «по заявлению Шор» маскируется. Это список подсказок в коде, не модель.
- **одиночная фамилия без такой подсказки**, имени, отчества и инициалов, если её нет в словаре Wikidata и у неё
  нет русского суффикса (-ов, -ин, -енко…): «В протоколе назван Шор». Остальные ФИО вне данных кейса заменяются
  меткой `[ФИО]` (`privacy/unknown_names.py`, словарь — CC0). Это главный остаточный риск.
  Сравнение словаря с офлайн-NER (Natasha) лежит в `tools/experiments/m05_ner/` и в пакет не входит: NER лучше
  ловит фамилии вне словаря, но лицензия весов неясная, поэтому в продукте остаётся словарь.
- имя без фамилии и отчества («Мария»); двойная фамилия через дефис, если ни одна часть не из словаря и без
  русского суффикса («Дюбуа-Леруа»). «Петров-Шор» маскируется целиком. Несклоняемые и иностранные фамилии
  вне правила основы; склонение — правило «основа + до трёх букв», а не словарь, поэтому слово с той же основой
  тоже может замениться;
- должности и подписи;
- дата рождения без подписи («дата рождения», «дата рожд.», «д.р.», «д/р», «г.р.», «г. рождения», «год рождения», «родился», «года рождения»). С подписью вырезается и запись `01.02.1980`, и форма `ГГГГ-ММ-ДД`, как даты в МЧД. «др.» — это «другие», не дата рождения. Без подписи дата остаётся, иначе из устава пропадут сроки;
- адрес без подписи, без индекса с городом и без улицы с номером. «ул. Ленина, 7», «дом № 7», «ул Ленина» и «просп. Мира» вырезаются. «5 процентов» и «5 руб.» домом не считаются, «напр.» улицей не считается;
- номера доверенностей, ОГРН и прочие реквизиты организаций (это не ПДн).

Распознавание — регулярные выражения, а не модель: пропуски возможны, тесты —
`tests/test_m05_pii_minimisation.py`. Если в строке с адресом юридического лица есть и адрес человека, он
остаётся вместе с ней. Отбор строк по словам может отрезать ограничение без этих слов: тогда
факта нет и кейс уходит на разбор человеку, а не получает подтверждение.

## К пилоту

- Хранилище кейсов в контуре банка со сроками хранения и удалением по запросу субъекта.
- Ключи журнала, псевдонимизации и подписи — в хранилище секретов банка. Ключи стенда в пилоте не используются.
- OIDC банка вместо статических токенов.
- Согласовать [модель угроз](THREAT_MODEL.md) с ИБ. Ориентиры — ГОСТ Р 57580.1 и требования к защите ПДн, набор мер выбирает банк.
- В логах — хеши отчётов и идентификаторы кейсов, без документов.
