# Для жюри

Здесь питч на три минуты, сценарий демо, трудные вопросы и метрики с источниками. Каждое число здесь есть в [`evidence.json`](../evidence.json) или в [реестре утверждений](../CLAIMS_REGISTRY.md), номер строки реестра указан в скобках.

## Питч, 3 минуты

**0:00–0:30. Проблема.** Представитель компании приходит в банк с машиночитаемой доверенностью. Сотрудник вручную сводит МЧД, выписку ЕГРЮЛ и устав и решает, можно ли этому человеку подписать платёж за компанию сегодня. Ошибка в сторону «да» даёт право подписи тому, чьи полномочия уже закончились. По данным Банка России, за девять месяцев 2026 года без согласия юрлиц проведено 2529 операций на 2,1 млрд руб.; в III квартале средняя операция — около 0,75 млн руб., примерно в 49 раз больше средней по всем клиентам, а возмещено компаниям около десятой части (M-07, M-15, M-52).

**0:30–1:15. Решение.** «Мандат» отвечает на один вопрос: может ли этот человек провести эту операцию от имени этой компании в этот день. Ответ выносят 39 правил, у каждого есть норма и тест (C-01). Ответов четыре: «подтверждено», «опровергнуто», «на разбор», «недостаточно данных». Если данных не хватает, «да» не будет. Языковая модель только предлагает цитату из устава, вердикт она не меняет ([ADR-001](adr/ADR-001-verdict-ownership.md)).

**1:15–2:15. Доказательства.**
- На синтетическом корпусе из 294 кейсов и 49 видов дефектов ложных «подтверждено» 0 из 288, верхняя граница 95 % — 1,3 % (C-03).
- Без человека решается 38,8 % корпуса, ошибок среди этих решений нет (C-05).
- 8814 мутаций сценариев не дали ни одного ложного «подтверждено» (C-17).
- Независимая реализация на Cedar совпала на всех 384 цепочках передоверия (C-06).
- Каждое решение пишется в журнал с хеш-цепочкой и деревом Меркла. Банк выдаёт удостоверение со статусом, а отмена МЧД отзывает его по всей цепочке (C-09–C-11).
- 2040 автотестов проходит (C-13).

**2:15–3:00. Что дальше.** Ядро работает. Для пилота банк подключает свои источники через готовые порты: реестр МЧД, ЕФРСБ, СКЗИ для КЭП, а ЕГРЮЛ — через новый порт по тому же образцу. Юрист утверждает правила, по вопросам из [LEGAL_REVIEW](LEGAL_REVIEW.md). Затем идёт теневой режим на 50–100 обезличенных пакетах в течение шести недель ([PILOT](PILOT.md)). От банка нужны владелец процесса, регламент одной операции и юрист.

## Демо, 5 шагов

Подготовка: `./run-demo.sh` в Linux, macOS или WSL, время около 10 секунд. Подробные фразы — в [DEMO.md](DEMO.md).

1. `var/demo/01_ok.html`. Вердикт «на разбор»: всё сходится, но устав не разобран, а без него «да» не будет.
2. `var/demo/10_old_director_poa.html` и `05_director_changed.html`. Давняя смена директора даёт сигнал, свежая отправляет кейс на разбор (п. 1 ст. 188 ГК РФ).
3. Терминал, отмена и захват:
   ```bash
   mandat attest-verify var/demo/attestations/01_ok.json --public-key-file var/demo/public_key.txt --status-dir var/demo/status   # действует, код 0
   mandat monitor examples/events/takeover.json --status-dir var/demo/status
   mandat attest-verify var/demo/attestations/01_ok.json --public-key-file var/demo/public_key.txt --status-dir var/demo/status   # приостановлено, код 3
   ```
4. Вся цепочка одной командой: `mandat showcase`. Допуск платежа, отказ повтору и завышенной сумме, признаки захвата, отказ следующему платежу до списания денег, журнал и доказательство Меркла ([сценарий](DEMO.md#порядок)).
5. Журнал: `mandat journal-proof var/demo/journal.jsonl --seq 3`. Аудитор получает доказательство одной записи без всего журнала.

Если терминал не работает, используйте готовые карточки в [docs/demo/](demo/).

## Трудные вопросы

| Вопрос | Ответ |
|---|---|
| 0 ложных «да» — это точность 100 %? | Нет. Корпус синтетический, дефекты в него заложили мы сами. Это проверка логики, а не точность на потоке банка. Точность покажет теневой режим пилота |
| Почему в демо только одно «подтверждено»? | Так задумано: при любом сомнении кейс уходит человеку. Цель — ни одного ложного «да», а не максимум автоматизации |
| ФНС уже показывает статус МЧД. Зачем вы? | Статус в реестре — одно правило из 39. Остальные проверяют смену руководителя, передоверие, сроки, устав и то, покрывает ли МЧД конкретную операцию ([конкуренты](COMPETITORS.md)) |
| Решение принимает ИИ? | Нет. Вердикт выносят правила. Модель по умолчанию выключена и только предлагает факт с дословной цитатой из устава |
| КЭП проверяется? | На стенде нет: СКЗИ не подключено, статус подписи — «не проверено». В профиле `strict` это блокирует «подтверждено». Порт `SignaturePort` для СКЗИ банка готов |
| Правила утверждены юристом? | Нет, все 39 пока черновики. До утверждения `strict` ничего не подтверждает автоматически. Вопросы юристу готовы |
| Кто отвечает за ошибочное «да»? | Решение об операции принимает банк по своему регламенту. Каждый вывод хранит норму и поле документа и пишется в журнал, где правку видно, поэтому ошибку можно разобрать до конкретного правила |
| Как насчёт 152-ФЗ? | Ядро не ходит во внешнюю сеть. В модель уходят строки устава о полномочиях: ФИО становятся метками, дата рождения и адрес человека вырезаются, номера становятся псевдонимами. Сумма сделки остаётся. Фамилия без подсказки может остаться. Это не обезличивание, оценку соответствия мы не проходили ([защита данных](DATA_PROTECTION.md)) |
| Откуда деньги на слайде? | База — данные Банка России о хищениях у юрлиц за I–III кварталы 2026 года и число бизнес-клиентов из отчётности ВТБ. Доли событий, минуты и доля ВТБ — параметры трёх сценариев; пилот калибрует их за первые две недели (C-15, C-16) |
| С НДС ли посчитана окупаемость? | Да. НДС 22 % на внедрение, сопровождение правил и поддержку банк не принимает к вычету (п. 5 ст. 170 НК РФ), поэтому он в затратах. Лицензия на ПО из реестра российского ПО — без НДС (пп. 26 п. 2 ст. 149 НК РФ); заявка в реестр — во II квартале 2027 года, до начала подписки. Если ПО ещё не в реестре, НДС ляжет и на лицензию: окупаемость около 8,4 месяца вместо 7,8 ([экономика](ECONOMICS.md#юнит-экономика-одной-проверки)) |
| Подпись удостоверения — ГОСТ? | Нет, на стенде Ed25519. В пилоте подпись меняется на ГОСТ через СКЗИ банка. Каноническая запись, хеш и proofValue совпадают с векторами eddsa-jcs-2022 (C-10) |
| Подлинное удостоверение — значит, операцию можно проводить? | Нет. Подпись удостоверения доказывает подлинность, но не право: операция разрешается только после проверки актуального статуса (отзыв/приостановка) и полномочий на конкретное действие. В пилотном и промышленном режимах проверка без списка статусов не даёт разрешения — только вывод «подлинно» |
| Поддерживаете SD-JWT VC / кошелёк EUDI? | Формат SD-JWT VC остаётся черновиком IETF; мы следим за профилем EUDI (SD-JWT VC/mdoc) и рассматриваем его как направление совместимости, а не как реализованную функцию |
| Что будет, когда МЧД истечёт? | За 30 дней до конца срока мониторинг поднимает тревогу «истекает»: банк напоминает клиенту перевыпустить МЧД, пока платёж не сорвался. Срок передоверия — не дольше основной МЧД (п. 4 ст. 187 ГК РФ), поэтому считается самый ранний в цепочке. Срок прошёл, а реестр промолчал — удостоверения всё равно отзываются (подп. 1 п. 1 ст. 188 ГК РФ) |
| Если реестр МЧД не ответил? | Ответ будет «недостаточно данных», а не «действует». Молчание источника не считается хорошей новостью |
| Отмену у нотариуса увидите? | Пока нет: подключён только реестр МЧД ФНС. Реестр нотариата — отдельный источник, его подключим на пилоте |
| Насколько это быстро? | Медиана менее 4 мс на кейс, 95 % кейсов быстрее 6 мс. Замер сделан на машине сборки `evidence.json`, без сети и модели (C-14) |
| Контур уже это делает? | По открытым материалам Контура Диадок проверяет даты действия МЧД и совпадение представителя с сертификатом, но «проверять полномочия подписанта Диадок не может». Источник мы видели только в выдаче поиска. Мы проверяем именно полномочие на операцию |
| Астрал и МИГ24 уже продают банкам API МЧД. Зачем вы? | Их API отвечают, действует ли МЧД и какие полномочия в ней записаны. Для нас это вход, а не замена: «Мандат» сверяет МЧД с ЕГРЮЛ на дату, уставом, цепочкой передоверия и конкретной операцией и пишет норму и поле документа. Их API подключается адаптером порта реестра (M-55, [конкуренты](COMPETITORS.md)) |
| Где такое уже работает? | В Нидерландах и Швеции: Signicat и шведское бюро UC продают ответ «может ли этот человек подписать за компанию» по данным торговых реестров, Signicat — с допустимыми сочетаниями подписантов (M-37, M-53). В России такого слоя над МЧД, ЕГРЮЛ и уставом нет |
| Это if-else на синтетике, которую вы сами сгенерировали? | Корпус наш, и это проверка логики. Ценность — в нормах: у каждого из 39 правил есть статья и тест. Свойство передоверия независимо проверено на Cedar. Точность на потоке даст теневой пилот |
| Подложат поддельную выписку ЕГРЮЛ? | В `strict` данные из пакета клиента не закрывают обязательный источник. В `demo` это видно на плашке «Режим стенда» |
| Что банк обязан зафиксировать по 115-ФЗ? | Номер, дату выдачи и срок документа-основания. Они есть в отчёте (`chain.documents`) и в таблице карточки; если срок в МЧД не указан, показан срок по закону |
| Как с 821-П и ГОСТ Р 57580.1? | Соответствие не заявляем: меры стенда и пробелы перечислены в [REGULATORY](REGULATORY.md). Признаки ОД-2506 остаются в антифроде банка, «Мандат» передаёт ему события по подписанному вебхуку |
| Если запрос придёт от ИИ-агента (AP2, агентные платежи)? | По ГК РФ и 63-ФЗ представитель — лицо, а не программа, и МЧД агенту не выдают. «Мандат» проверяет полномочие человека, от чьего имени действует агент, на конкретную операцию. Идея AP2 та же: полномочие проверяется под конкретную операцию |
| Реестр ФНС ведь ищет МЧД не только по номеру? | Да, по открытым обзорам с 01.03.2026 — по трём параметрам: номер, ИНН доверителя, ИНН представителя (M-43). Порт «Мандата» передаёт все три |
| Это требование только российское? | Нет. FATF требует проверить, что представитель уполномочен; в ЕС с 10.07.2027 — Регламент 2024/1624, проект RTS AMLA добавляет объём полномочия (M-12, M-13). Выписка о компании ЕС по Директиве 2025/25 показывает, действуют ли представители по одному или совместно; ту же ось проверяет правило R-JNT-001 (M-14) |
| Удостоверение на одну дату допустит операцию в другую? | Нет, если допуск вызван с запросом, а момент проверки ставит сервер. Дата сверяется с днём по Москве, организация — с ИНН. В `pilot` и `prod` запрос обязателен; на стенде вызов без запроса привязку не проверяет. Срок удостоверения не длиннее 30 дней и, если в отчёте есть сроки документов цепочки, не длиннее самого раннего из них. Без этих сроков истечение МЧД видно только по `POA_EXPIRED` |
