# Для жюри

Коротко: питч на три минуты, сценарий демо, трудные вопросы с честными ответами и метрики с источниками. Каждое число здесь есть в [`evidence.json`](../evidence.json) или в [реестре утверждений](../CLAIMS_REGISTRY.md), номер строки реестра указан в скобках.

## Питч, 3 минуты

**0:00–0:30. Проблема.** Представитель компании приходит в банк с машиночитаемой доверенностью. Сотрудник вручную сводит МЧД, выписку ЕГРЮЛ и устав и решает, можно ли этому человеку подписать платёж за компанию сегодня. Ошибка в сторону «да» даёт право подписи тому, чьи полномочия уже закончились. По данным Банка России, в I квартале 2026 года без согласия юрлиц проведено 818 операций на 573 млн руб., в среднем около 0,7 млн руб. на операцию (M-07).

**0:30–1:15. Решение.** «Мандат» отвечает на один вопрос: может ли этот человек провести эту операцию от имени этой компании в этот день. Ответ выносят 39 правил, у каждого есть норма и тест (C-01). Ответов четыре: «подтверждено», «опровергнуто», «на разбор», «недостаточно данных». Если данных не хватает, «да» не будет. Языковая модель только предлагает цитату из устава, вердикт она не меняет ([ADR-001](adr/ADR-001-verdict-ownership.md)).

**1:15–2:15. Доказательства.**
- На синтетическом корпусе из 294 кейсов и 49 видов дефектов ложных «подтверждено» 0 из 288, верхняя граница 95 % — 1,3 % (C-03).
- Без человека решается 38,8 % корпуса, ошибок среди этих решений нет (C-05).
- 8814 мутаций сценариев не дали ни одного ложного «подтверждено» (C-17).
- Независимая реализация на Cedar совпала на всех 384 цепочках передоверия (C-06).
- Каждое решение пишется в журнал с хеш-цепочкой и деревом Меркла. Банк выдаёт удостоверение со статусом, а отмена МЧД отзывает его по всей цепочке (C-09–C-11).
- 865 автотестов проходят (C-13).

**2:15–3:00. Что дальше.** Ядро работает. Для пилота банк подключает свои источники через готовые порты: реестр МЧД, ЕФРСБ, СКЗИ для КЭП, а ЕГРЮЛ — через новый порт по тому же образцу. Юрист утверждает правила, по вопросам из [LEGAL_REVIEW](LEGAL_REVIEW.md). Затем идёт теневой режим на 50–100 обезличенных пакетах в течение шести недель ([PILOT](PILOT.md)). От банка нужны владелец процесса, регламент одной операции и юрист.

## Демо, 4 шага

Подготовка: `./run-demo.sh` (на Windows `.\run-demo.ps1`), время около 10 секунд. Подробные фразы — в [DEMO.md](DEMO.md).

1. `var/demo/01_ok.html`. Вердикт «на разбор»: всё сходится, но устав не разобран, а без него «да» не будет.
2. `var/demo/10_old_director_poa.html` и `05_director_changed.html`. Давняя смена директора даёт сигнал, свежая отправляет кейс на разбор (п. 1 ст. 188 ГК РФ).
3. Терминал, отмена и захват:
   ```bash
   mandat attest-verify var/demo/attestations/01_ok.json --public-key-file var/demo/public_key.txt --status-dir var/demo/status   # действует, код 0
   mandat monitor examples/events/takeover.json --status-dir var/demo/status
   mandat attest-verify var/demo/attestations/01_ok.json --public-key-file var/demo/public_key.txt --status-dir var/demo/status   # приостановлено, код 3
   ```
4. Журнал: `mandat journal-proof var/demo/journal.jsonl --seq 3`. Аудитор получает доказательство одной записи без всего журнала.

Если терминал не работает, используйте готовые карточки в [docs/demo/](demo/).

## Трудные вопросы

| Вопрос | Честный ответ |
|---|---|
| 0 ложных «да» — это точность 100 %? | Нет. Корпус синтетический, дефекты в него заложили мы сами. Это проверка логики, а не точность на потоке банка. Точность покажет теневой режим пилота |
| Почему в демо только одно «подтверждено»? | Так задумано: при любом сомнении кейс уходит человеку. Цель — ни одного ложного «да», а не максимум автоматизации |
| ФНС уже показывает статус МЧД. Зачем вы? | Статус в реестре — одно правило из 39. Остальные проверяют смену руководителя, передоверие, сроки, устав и то, покрывает ли МЧД конкретную операцию ([конкуренты](COMPETITORS.md)) |
| Решение принимает ИИ? | Нет. Вердикт выносят правила. Модель по умолчанию выключена и только предлагает факт с дословной цитатой из устава |
| КЭП проверяется? | На стенде нет: СКЗИ не подключено, статус подписи — «не проверено». В профиле `strict` это блокирует «подтверждено». Порт `SignaturePort` для СКЗИ банка готов |
| Правила утверждены юристом? | Нет, все 39 пока черновики. До утверждения `strict` ничего не подтверждает автоматически. Вопросы юристу готовы |
| Кто отвечает за ошибочное «да»? | Решение об операции принимает банк по своему регламенту. Каждый вывод хранит норму и поле документа и пишется в журнал, где правку видно, поэтому ошибку можно разобрать до конкретного правила |
| Как насчёт 152-ФЗ? | Ядро не ходит во внешнюю сеть. Перед отправкой текста в модель ИНН, СНИЛС, паспорт, счёт, телефон и почта заменяются псевдонимами. Оценку соответствия мы не проходили ([защита данных](DATA_PROTECTION.md)) |
| Откуда деньги на слайде? | Данные о хищениях и число клиентов взяты из открытых источников. Доли событий, минуты и долю ВТБ задали мы сами. Поэтому это сценарии, а не прогноз (C-15, C-16) |
| Подпись удостоверения — ГОСТ? | Нет, на стенде Ed25519. В пилоте подпись меняется на ГОСТ через СКЗИ банка. Совместимость с внешними верификаторами VC мы не проверяли |
| Если реестр МЧД не ответил? | Ответ будет «недостаточно данных», а не «действует». Молчание источника не считается хорошей новостью |
| Отмену у нотариуса увидите? | Пока нет: подключён только реестр МЧД ФНС. Реестр нотариата — отдельный источник, его подключим на пилоте |
| Насколько это быстро? | Медиана около 2 мс на кейс, 95 % кейсов быстрее 3 мс. Замер сделан на машине разработчика, без сети и модели (C-14) |
