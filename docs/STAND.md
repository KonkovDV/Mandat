# Стенд для жюри: консоль сотрудника

Консоль сотрудника банка на `/console/` поверх HTTP API «Мандата». Жюри проходит путь банка за пять минут: проверка полномочия с доказательством, пояснение консультанта, очередь юриста со сроками, допуск платежа в ДБО и остановка захвата, прогон кейсов с нулём ложных «ПОДТВЕРЖДЕНО». Данные вымышленные, профиль `demo`.

Консоль включается флагом `MANDAT_STAND=1` и работает только в режимах `demo`, `dev`, `test`: в `pilot` и `prod` сервис с этим флагом не стартует. Каждая сессия браузера получает свои учётные записи API — оператор, юрист (`reviewer` со специализацией `lawyer`) и система ДБО (`dbo`); токены остаются на сервере, кейсы одной сессии другой не видны, прав администратора и удаления у консоли нет.

## Что нужно

- Сервер Ubuntu 22.04 или 24.04, доступ root, открытые порты 80 и 443.
- Домен, запись A которого указывает на сервер: без неё сертификат Let's Encrypt не выпустится и стенд останется на HTTP.
- Для модели-советника — ключ OpenRouter. Без ключа консультант отвечает по фактам отчёта и разбору устава.

## Одна команда

```bash
git clone https://github.com/konkovdv/Mandat.git && cd Mandat
bash scripts/deploy_stand.sh stand.example.ru
```

Скрипт ставит Python 3.11+ и зависимости из lock-файлов с хешами, заводит пользователя `mandat` и службу `mandat-stand` с перезапуском, пишет `/etc/mandat-stand.env`, настраивает nginx и выпускает сертификат. Он же готовит сервер к работе без присмотра — это раздел «Эксплуатация» ниже. В конце он сам проверяет стенд — здоровье, страницу, демо-кейс, удостоверение и допуск платежа, отказ HEAD на маршруте с действием, заголовок HSTS — и печатает адрес. Повторный запуск обновляет код и перезапускает службу; настройки в `/etc/mandat-stand.env` сохраняются.

Модель-советник через OpenRouter: ключ передаётся переменной окружения запуска и попадает только в `/etc/mandat-stand.env` с правами 600.

```bash
MANDAT_STAND_LLM_KEY=<ключ OpenRouter> bash scripts/deploy_stand.sh stand.example.ru
```

Скрипт записывает `MANDAT_LLM_BASE_URL=https://openrouter.ai/api/v1`, `MANDAT_LLM_ALLOWED_HOSTS=openrouter.ai`, `MANDAT_LLM_MODEL`, ключ, `MANDAT_LLM_EXTRA='{"provider":{"data_collection":"deny"},"usage":{"include":true}}'` (только провайдеры без хранения запросов и стоимость вызова в ответе) и `MANDAT_LLM_BUDGET_USD_PER_DAY` — потолок расхода за день, 1 $ по умолчанию, другой — `MANDAT_STAND_LLM_BUDGET`. Модель по умолчанию — `mistralai/mistral-small-3.2-24b-instruct`: открытые веса под Apache 2.0, ту же модель банк запускает на своём GPU. Быстрее и дешевле через API — `MANDAT_STAND_LLM_MODEL=deepseek/deepseek-v4-flash`. Почему выбрана эта модель — в [замере моделей](ADVISORY_MODELS.md). `MANDAT_STAND_LLM_KEY=off` снимает модель; повторный запуск без ключа дописывает недостающие `MANDAT_LLM_EXTRA` и бюджет, ключ и модель не трогает. В модель уходят только строки устава о полномочиях, ФИО и реквизиты заменены метками; её ответ — справка, вердикт не меняет.

Ещё переменные запуска: `MANDAT_STAND_EMAIL` — почта для Let's Encrypt, `MANDAT_STAND_PORT` — порт службы (8000), `MANDAT_STAND_SWAP_MB` — размер swap-файла (1024), `MANDAT_STAND_FAIL2BAN=0` — без fail2ban, `MANDAT_STAND_FAIL2BAN_IGNORE` — адреса и сети, которые fail2ban не банит (свой адрес, NAT жюри).

## Проверка

```bash
curl -s https://stand.example.ru/health      # "console": true и "commit" — коммит, из которого собран стенд
journalctl -u mandat-stand -n 50             # журнал службы
```

Дальше — открыть `https://stand.example.ru/console/` и пройти вкладки: «Проверка» (демо-кейс «Сумма выше порога одобрения по уставу» даёт НА РАЗБОР с цитатой устава и статьёй ГК РФ), «Консультант» (пояснение и шлюз на подставных ответах модели), «Юрист» (взять кейс, решить), «ДБО» (платёж допущен, повтор, завышенная сумма и захват остановлены), «Прогон» (ложных ПОДТВЕРЖДЕНО: 0).
Вкладка «Аналитика» — для руководителя банка: вердикты проверок сессии и доля, которая уходит к человеку, повторные клиенты с реестром заключений, юнит-экономика проверки из финансовой модели, ноль ложных ПОДТВЕРЖДЕНО и число автотестов, расход модели и ответы из кэша; у каждого числа назван источник (ключ `evidence.json`, сессия, счётчики модели), вкладка только читает, а `evidence.json` и значения модели скрипт кладёт рядом с `BUILD`.

## Расход модели

Консультант бережёт ключ и не заставляет ждать:

- **Кэш.** Ответ модели, который шлюз принял целиком (все факты с дословной цитатой или пустой список), хранится в памяти по SHA-256 обезличенного запроса и модели: 256 записей, сутки. Тот же устав второй раз модель не читает — демо-кейсы повторяются, это главная экономия. Ответ не JSON, с отброшенным фактом или ошибка в кэш не попадают.
- **Предохранитель.** Три неудачи подряд — сеть, тайм-аут, ответ не JSON, ни одного принятого факта, ответ позже 8 секунд — и модель на паузе 120 секунд: пояснение сразу собирается из фактов отчёта, без ожидания. Затем один пробный вызов решает, вернуть ли модель.
- **Дневной бюджет.** Стоимость каждого вызова берётся из `usage.cost` ответа OpenRouter. Когда расход за день по Москве доходит до потолка, модель выключена до 00:00 МСК, и консоль пишет, что ответ дают только правила. Принятые ответы из кэша при этом показываются: они ничего не стоят.
- **Счётчики.** Вызовы, неудачи, открытия предохранителя, попадания в кэш, токены, расход за день и остаток бюджета видны в блоке «Расход модели» на вкладке «Прогон» и в `/health` (ключ `model`). Ключа, текста запросов и ПДн там нет.

Пороги — в `/etc/mandat-stand.env`: `MANDAT_LLM_BREAKER_FAILURES` (3), `MANDAT_LLM_BREAKER_SECONDS` (120), `MANDAT_LLM_BUDGET_USD_PER_DAY` (1, `0` выключает модель), `MANDAT_LLM_CACHE_ENTRIES` (256, `0` выключает кэш), `MANDAT_LLM_CACHE_SECONDS` (86400); после правки — `systemctl restart mandat-stand`. Счётчики, расход дня и кэш живут в памяти службы и обнуляются при перезапуске. Жёсткий потолок денег — лимит ключа в кабинете OpenRouter: задайте его при выпуске ключа.

## Эксплуатация

- **Время.** Часовой пояс сервера — `Europe/Moscow`, синхронизация времени включена: день бюджета, расписание копий и журналы nginx — по Москве.
- **Память.** На машине меньше 2 ГБ скрипт включает swap-файл `/swapfile` и `vm.swappiness=10`.
- **Журналы.** Служба пишет только в journald, файлов журнала у неё нет, logrotate ей не нужен. journald ограничен 200 МБ и месяцем истории. Журнал аудита `journal.jsonl` сам делится на сегменты; logrotate его не трогает: обрезка разорвала бы цепочку хешей.
- **Перезапуск.** `Restart=always`, не больше 5 запусков за 5 минут. Сторож `mandat-stand-watchdog.timer` раз в минуту спрашивает `/health` и после трёх неудач подряд перезапускает службу, в том числе упавшую по пределу запусков; остановленную оператором (`systemctl stop`) не поднимает. Его журнал: `journalctl -u mandat-stand-watchdog`.
- **Копии.** `mandat-stand-backup.timer` в 03:15 МСК запускает `mandat backup`: журнал аудита копируется под его блокировкой записи и сразу проверяется, базы SQLite — их собственным резервным копированием, остальные файлы каталога `/var/lib/mandat-stand` (разборы, заключения) — по одному, атомарно. Служба при этом работает. Копии лежат в `/var/backups/mandat-stand/mandat-ГГГГММДД-ЧЧММСС` (права 700, внутри `MANIFEST.json` с SHA-256 каждого файла), хранятся последние 14. Временные каталоги демо-издателя в копию не входят: ключи их списков жили в памяти процесса. Настройки `/etc/mandat-stand.env` в копию не входят: в них ключ. Копия вне расписания: `systemctl start mandat-stand-backup`; выкладка снимает одну копию сама.
- **Восстановление.** `systemctl stop mandat-stand`, `cp -a /var/backups/mandat-stand/<копия>/data/. /var/lib/mandat-stand/`, `chown -R mandat:mandat /var/lib/mandat-stand`, `systemctl start mandat-stand`, затем `mandat journal-verify /var/lib/mandat-stand/journal.jsonl`.
- **fail2ban** включён по умолчанию: `sshd` — 5 неудачных входов за 10 минут, бан на час; `nginx-limit-req` — 300 отказов лимита API за минуту, бан на 10 минут; `mandat-stand-auth` — 20 ответов 401 и 403 на `/v1/` и `/access/v1/` за 10 минут, бан на час. Зона тяжёлых действий консоли и файлы страницы в бан не ведут: в их лимит упираются люди за одним NAT. Настройка, которая не проходит `fail2ban-client -t`, снимается, остальное работает. Кто в бане: `fail2ban-client status mandat-stand-auth`.
- **Обновления.** `unattended-upgrades` ставит обновления безопасности каждый день, сервер сам не перезагружается: после обновления ядра появляется `/var/run/reboot-required`, перезагрузку делает оператор.

## Откат

```bash
bash scripts/deploy_stand.sh rollback
```

Возвращает предыдущую выкладку из `/opt/mandat-stand/src.prev`, переустанавливает пакет, перезапускает службу и проверяет стенд. Другой путь — `git checkout <прежний коммит>` в папке проекта и повторный запуск скрипта с доменом.

## Что защищает стенд

- nginx: HTTPS с HSTS, `server_tokens off`, чужое имя хоста закрывается без ответа, `limit_req` по адресу на `/v1/`, `/access/v1/`, действия консоли и отдельно на тяжёлые действия (модель, прогон, шлюз), тело запроса до 1 МБ.
- Служба: только `127.0.0.1`, отдельный пользователь, systemd с `ProtectSystem=strict`, запись только в `/var/lib/mandat-stand`.
- Консоль: CSP без встроенных скриптов и стилей, `X-Frame-Options: DENY`, `noindex`, HEAD только на страницах и файлах, POST только `application/json` и без чужого `Origin`, тело до 512 КБ, cookie сессии `HttpOnly`, `SameSite=Strict`, `Secure`; один прогон за раз и не больше 50 кейсов; справка модели ждёт не дольше 8 секунд, на паузе предохранителя и после дневного бюджета — не ждёт вовсе.
- Журнал аудита `/var/lib/mandat-stand/journal.jsonl`: каждое создание и чтение кейса, решение юриста и допуск операции.

## Локально

```bash
MANDAT_STAND=1 mandat serve --port 8000     # http://127.0.0.1:8000/console/
```

## На пилоте

Консоль стенда — витрина. На пилоте банк подключает свой вход сотрудников вместо сессий браузера, учётные записи из `MANDAT_API_USERS` со сроком действия, общее хранилище и ключи (`MANDAT_ENV=pilot`, [запуск](RUN.md)), свою модель в контуре через `MANDAT_LLM_*` и реестр МЧД вместо фикстур демо-кейсов.

## HTTPS через API Gateway Yandex Cloud

Если Let's Encrypt не может проверить машину из-за рубежа, HTTPS даёт API Gateway: у шлюза свой адрес `*.apigw.yandexcloud.net` с доверенным сертификатом, а на машину он ходит по HTTP внутри облака. Свой домен не нужен.

1. Консоль Yandex Cloud → API Gateway → «Создать API-шлюз», вставить [спецификацию](../deploy/yandex-api-gateway.yaml), заменив `<IP>` на публичный IP машины и `<HOST>` на адрес, с которым запускали `deploy_stand.sh`.
2. Скопировать «Служебный домен» шлюза, например `d5d0example.apigw.yandexcloud.net`.
3. На машине перезапустить выкладку с этим доменом, чтобы консоль принимала запросы со страницы шлюза: `MANDAT_STAND_ORIGINS=d5d0example.apigw.yandexcloud.net bash scripts/deploy_stand.sh <HOST>`.
4. Стенд открывается по `https://<служебный домен>/console/`.

`MANDAT_STAND_ORIGINS` — хосты через запятую, без схемы; запрос с любого другого `Origin` консоль по-прежнему отклоняет.
