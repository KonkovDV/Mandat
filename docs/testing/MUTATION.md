# Мутационное тестирование `rules/checks.py`

Запускается вручную, в CI не входит: полный прогон на 8 потоках идёт около полутора часов. Настройка — `[tool.mutmut]` в `pyproject.toml`, инструмент — mutmut 3.8.0.

```bash
pip install mutmut==3.8.0 -r requirements/dev.lock && pip install -e .
mutmut run --max-children 8
mutmut results            # выжившие мутанты
mutmut show <имя>         # что именно изменено
```

`also_copy` переносит в `mutants/` каталоги `docs/` и `examples/`: без них тесты схемы манифеста и сквозные тесты не находят файлов. Тест сверки `evidence.json` исключён, потому что при любом мутанте хэш расходится заведомо.

Таймаут считается обнаружением: мутант зациклил проверку.

Что закрыли новые тесты (это настоящие пробелы, а не только текст сообщений):
- **R-EIO-002, свежий руководитель.** Ветка «предшественника нет», граница окна в 30 дней включительно, предшественник с той же даты, повторное назначение того же лица, хвост «приоритет P1» для операций высокого риска.
- **R-EIO-004.** Статус «в процессе ликвидации» не проверялся ни одним тестом. Банкротство представителя после нераспознанного статуса доверителя: мутант `continue → break` пропускал вторую сторону. Процедура, не подходящая к виду лица.
- **Порт реестра.** Кеш по нормализованному номеру, передача ИНН, обёртка порта, у которого есть только `status`, порт без параметров ИНН.
- **Часы.** Допуск 5 минут, наивное время считается UTC, учитывается зона +03:00.
- **Служебное.** `emit` переносит `norm_ref` и статус правила и скрывает следующий шаг у «подтверждает» и «справка». Повторная регистрация правила запрещена. Нормализация наименования: ё, кавычки, ООО и АО.

## Что выжило и почему не добиваем

- **78 мутантов в `_charter_info` и около 20 в `_org_status_egrul` / `_format_supports`.** Это текст справок. Решение зависит от эффекта, а не от формулировки; фиксировать каждую строку тестом значит закрепить редакцию текста, а не поведение.
- **`registry_query`, выбор представителя.** Во всех примерах заявитель — первый представитель МЧД, поэтому мутанты «предпочесть заявителя» эквивалентны на этих данных. Защита от чужого заявителя — R-ID-005, см. тест Red Team в `test_r11_mutation_kills.py`. Кандидат на следующий раунд: пример с двумя представителями.
- **`run_rules`, ветка `retired`.** В пакете нет выведенных из оборота правил, поэтому ветка не исполняется.
- **`_fresh_director`, ветки `or` для дат.** В ЕГРЮЛ примеров `valid_from` и `record_date` совпадают, поэтому мутанты эквивалентны.
