# Промт: презентация «Мандата» для трека ВТБ

Бриф, по которому собирается колода `submission/slides/Mandat_VTB.pptx`. Его можно отдать исполнителю (человеку или модели) целиком: в нём роль, цель, драматургия, дизайн-система, правила данных и чек-лист приёмки. Исполнение — `build_deck.js` и `graphics.js` в этой папке.

---

## 1. Роль

Ты — арт-директор и редактор питч-колод для финтеха с опытом банковского продукта, корпоративного права и ИБ. Ты собираешь колоду, по которой жюри банка за пять минут принимает решение: звать ли команду в теневой пилот. Каждое число ты подтверждаешь источником, каждое утверждение — границей. Ты не украшаешь: каждый элемент на слайде либо несёт смысл, либо удаляется.

## 2. Контекст и цель

| Что | Значение |
|---|---|
| Событие | «Академия Финтеха 2026», трек ВТБ «Финтех без границ», задача «Онбординг и проверка полномочий»; онлайн-питч 10–15.11.2026, финал 11.12.2026 |
| Продукт | «Мандат» — движок, который отвечает, вправе ли человек провести операцию от имени компании на дату, и доказывает ответ полем документа, записью ЕГРЮЛ и нормой |
| Решение, которого мы добиваемся | согласие на шестинедельный теневой пилот через Акселератор ВТБ на праве подписи платёжных поручений по МЧД |
| Аудитория | жюри банка: владелец продукта, риск и антифрод, юрист, ИБ, технолог; эксперты Финансового университета |

## 3. Главная мысль и драматургия

**Одна фраза.** «Мандат» отвечает, вправе ли человек провести операцию за компанию в этот день, и доказывает ответ; неизвестное никогда не становится «да». Мы просим шесть недель теневого пилота, чтобы измерить это на данных ВТБ.

**Каркас.** Ответ сначала (принцип пирамиды Минто), затем SCQA: ситуация → осложнение → вопрос → ответ. Порядок блоков — как в шаблонах Sequoia и YC: проблема, почему сейчас, решение, продукт, доказательства, бизнес-модель, рынок и конкуренты, команда, запрос. Структура выдерживает «горизонтальное чтение»: если прочитать только заголовки слайдов подряд, получается связный рассказ (практика McKinsey). Каждый слайд проходит «тест взгляда» Нэнси Дуарте: главное понятно за три секунды.

**Заголовок — это вывод**, а не тема: «Ноль ложных „подтверждено“ на 288 кейсах», а не «Качество». Не длиннее двух строк, без точки в конце.

**Порядок питча** (тайминг — в заметках докладчика, всего ≈5:00):

## 4. Правила данных

1. Числа о продукте — только из `evidence.json` и `tests/test_redteam_fuzz.py`, подставляются кодом. Рыночные и правовые факты — только из `CLAIMS_REGISTRY.md` (строки C-xx и M-xx) вместе с их границей.
2. У каждого слайда с фактами есть строка источника внизу: кто, что, дата.
3. Синтетика называется синтетикой. Допущения называются допущениями. Вторичный источник называется вторичным.
4. Запрещены формулировки из `BANNED_CLAIMS.txt`. Проверка — `python scripts/lint_claims.py` и `finish_deck.py`.
5. Ничего не придумывать: вывод терминала и скриншоты — настоящие, снятые с `./run-demo.sh`. Пропуски в выводе обозначаются «…».
6. Персональные данные — только вымышленные данные демо-кейсов и контакты команды.

| Роль | HEX | Где |
|---|---|---|
| Тёмно-синий ВТБ | `0A2973` | заголовки, плашки выводов, фон обложки |
| Кобальт | `004CBC` | акценты, значки, ссылки, мелкий цветной текст |
| Голубой ВТБ | `00AAFF` | только графика и текст на тёмном фоне |
| Текст | `0B1F44` | основной текст |
| Второй план | `42557A`, `62718F` | подписи, источники |
| Фон | `F3F6FB`, карточки `FFFFFF`, линии `DCE4F0` | |
| Вердикты | подтверждено `1A9F68`, на разбор `F5A300`, опровергнуто `E5484D`, недостаточно данных `6B7A99` | только в паре с текстом и значком |

**Шрифт.** Golos Text (ParaType, OFL). Фирменный VTB Group UI не используется: лицензия только для Группы ВТБ. Шкала: обложка 56; заголовок слайда 26 полужирный; крупное число 40–46; подзаголовок карточки 14–16 полужирный; текст 12–14; подписи 10,5–11; источники 10. Минимум на экране — 10 pt.

**Сетка.** Поля 0,6 дюйма; межколонник 0,25; зона заголовка 0,3–1,56; контент 1,72–6,72; подвал 6,86–7,32. Заголовки на одном месте на всех контентных слайдах.

**Компоненты.** Карточка (скругление 0,12, линия `DCE4F0`, мягкая тень), плитка значка (скругление 28 %), плашка вердикта (оттенок + точка + текст), плашка вывода (тёмно-синяя), таблица (шапка тёмно-синяя, зебра), ось времени, окно браузера, окно терминала.

**Значки.** Lucide, линия 2, один цвет на плитке. Никаких эмодзи и клипарта.

**Диаграммы** (Тафти, Фью, Зелязны): родные диаграммы PowerPoint; ось значений скрыта, подписи данных прямо на столбцах; без сетки, без легенды при одном ряде; ось от нуля; один акцентный цвет или цвета вердиктов.

**Изображения.** Только настоящие: скриншот карточки `mandat demo`, фото команды. Графика рисуется кодом, исходники SVG — в `assets/svg/` для Figma.

**Без** декоративных полос по краю, подчёркиваний заголовков, градиентного текста, анимаций.

## 6. Русская типографика

- Неразрывный пробел: после одно- и двухбуквенных слов (в, и, с, к, на, по, от, до, не), перед тире, между числом и единицей (0,7 млн ₽, 5 рабочих дней), в «ст. 188», «п. 1», «№ 1001», «ГК РФ», в инициалах «И. П.», между группами разрядов (480 000).
- Кавычки «ёлочки», внутри — „лапки“. Тире «—» с пробелами, в диапазонах — «–» без пробелов (10–15). Знак «≈» для оценок. Буква «ё» там, где она есть.
- Числа: десятичная запятая, проценты без пробела (11,3%), валюта после числа (₽).

## 7. Доступность (WCAG 2.2 AA)

- Контраст текста не ниже 4,5:1, крупного (от 18 pt или 14 pt полужирного) — не ниже 3:1. Голубой `00AAFF` на белом под текст не используется.
- Смысл не передаётся одним цветом: у вердикта всегда есть слово и значок.
- Заголовки — в заполнителях заголовка (порядок чтения, навигация). У картинок есть alt-текст, значки помечены декоративными.
- Язык текста — русский (`ru-RU`): проверка орфографии в PowerPoint работает.

## 8. Заметки докладчика

Формат: `[мм:сс–мм:сс]` и живая речь, примерно 2,5 слова в секунду. В конце — фраза-переход к следующему слайду. Цифры в заметках те же, что на слайде.
