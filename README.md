# Мандат

**Проблема.** Представитель компании приходит в банк с машиночитаемой доверенностью (МЧД). Сотрудник вручную сводит МЧД, выписку ЕГРЮЛ (Единый государственный реестр юридических лиц) и устав и решает, можно ли пустить этого человека к операции. Ошибка в сторону «да» даёт право подписи тому, чьи полномочия уже закончились.

**Что делает «Мандат».** Отвечает на один вопрос: *может ли этот человек провести эту операцию от имени этой компании в этот день?* Ответ выносят правила с привязкой к норме, к каждому приложено, на чём он держится: поле МЧД, запись ЕГРЮЛ, фраза устава, статья закона. Если данных не хватает, «да» не будет.

Проект для трека ВТБ «Финтех без границ: банк будущего для бизнеса и клиентов» соревнования «Академия Финтеха 2026».

**Статус.** Это стенд для жюри, не пилот и не промышленный контур. На GitHub одна ветка, `main`; зелёность показывает значок CI выше. Чего продукт не делает — в [LIMITS.md](LIMITS.md). Как устроены проверка, безопасность и вклад — [SECURITY.md](SECURITY.md), [CONTRIBUTING.md](CONTRIBUTING.md).

## Что уже работает

- **Ни одного ложного «да» на синтетическом корпусе:** 0 из 288 кейсов, где подтверждать нельзя; верхняя граница 95 % — 1,3 %, а по 48 видам дефектов, если считать кейсы одного вида зависимыми, — 7,4 % (C-03).
- **38,8 % корпуса из сгенерированных нами кейсов решается без человека**, ошибок среди этих решений нет, верхняя граница риска 3,2 % (C-05).
- **39 правил с привязкой к закону:** у каждого статья, следующий шаг для сотрудника и тест (C-01).
- **Журнал, который выдаёт правку:** хеш-цепочка с HMAC и дерево Меркла; аудитор получает доказательство одной записи без всего журнала (C-09).
- **Удостоверение со статусом:** любую систему банка, например ДБО или антифрод, можно научить проверять его без доступа к базе; отмена основной МЧД отзывает удостоверения по всей цепочке (C-10, C-11).
- **8814 мутаций сценариев:** ложных «подтверждено» и падений нет (C-17); свойство передоверия совпадает со второй, независимой реализацией на Cedar на всех 384 цепочках (C-06).
- **Воспроизводимо:** демо одной командой, 1491 автотест, все числа собирает код в `evidence.json` (C-13).

**Границы.** Числа выше получены на синтетике, которую мы сгенерировали сами; точность на потоке банка не измерялась. Все 39 правил — черновики (`draft`), юрист банка их не утверждал. КЭП, реестр МЧД ФНС и ЕГРЮЛ на стенде — заглушки и данные из кейса; ГОСТ-подпись придёт через СКЗИ банка. Подробно: [LIMITS.md](LIMITS.md).

## За 30 секунд

```mermaid
flowchart LR
    A["МЧД, ЕГРЮЛ, устав"] --> B["Цепочка полномочий на дату операции"]
    R["Реестр МЧД, ЕФРСБ"] --> C
    B --> C["39 правил с нормой"]
    C --> D["Вердикт: опровержение сильнее нехватки данных, нехватка сильнее «да»"]
    D --> E["Карточка для сотрудника, журнал, подписанное удостоверение"]
    F["Отмена МЧД или признаки захвата"] --> G["Статус удостоверения меняется"]
```

Языковая модель в этой цепочке только предлагает факт из устава с дословной цитатой. Вердикт она не меняет, по умолчанию выключена ([ADR-001](docs/adr/ADR-001-verdict-ownership.md)).

## Четыре ответа

| Ответ | Простыми словами |
|---|---|
| ПОДТВЕРЖДЕНО | Все обязательные проверки пройдены, возражений нет. Сотрудник видит рекомендованную роль и то, что в этом прогоне не проверялось |
| ОПРОВЕРГНУТО | Полномочия нет: например, доверенность отменена или передоверие запрещено. Показаны норма и поле документа |
| НА РАЗБОР | Есть спорное: свежая смена директора, порог в уставе, текстовое полномочие. Решает человек |
| НЕДОСТАТОЧНО ДАННЫХ | Какой-то обязательной проверки не было. Это не «доверенность действует», а список того, чего не хватает |

## Что не становится «да»

Даже если остальные проверки сходятся, «подтверждено» не ставится, когда:

- устав обязателен, а шаблоны закрыли только часть текста (R-CHR-002);
- от одной МЧД в один день выданы разные передоверия (R-SUB-009);
- в МЧД нет признака совместных полномочий, в том числе у одного представителя (R-JNT-001);
- у кода полномочия в классификаторе нет даты начала (R-COV-002);
- реестр опрошен после даты операции, а в снимке нет даты отмены (R-REG-001);
- в защищённом режиме список статусов проверен без момента времени.

Это поведение стенда, не юридическое заключение и не решение банка. Что этим не закрыто — [LIMITS.md](LIMITS.md) и [ответ на статический разбор](docs/audit/AUDIT-2026-10-16-EXPERT-RESPONSE.md).

## Что видит модель

Модель по умолчанию выключена. Когда её включают, она не меняет вердикт: предлагает факт из устава и должна процитировать его дословно.

В запрос попадают только строки о полномочиях. Перед этим текст чистят. ФИО из кейса становятся ролью. Чужая фамилия сразу после «заявлению» или «гражданина» становится меткой, даже если её нет в словаре. Дата рождения и домашний адрес вырезаются. Паспорт, СНИЛС, ИНН и телефон становятся псевдонимами, в том числе если их записали с пробелами, точками или со словом «номер».

Сумма в уставе остаётся. «Сделки свыше 1 000 000 руб.» и «8.100.000 рублей» модель должна видеть, иначе она не процитирует порог сделки. «2024 номер 123456» — номер договора, не паспорт.

Может остаться фамилия без подсказки («в протоколе назван Шор»), а также дата и адрес без подписи. Псевдоним по ключу сопоставим с человеком, поэтому текст для модели остаётся персональными данными. Оценку соответствия мы не проходили. Формы записи — [защита данных](docs/DATA_PROTECTION.md).

## Запустить демо

Одна команда, нужен Python 3.11+:

```bash
./run-demo.sh        # Windows: .\run-demo.ps1
```

Скрипт ставит пакет в локальный `.venv` и собирает 14 демо-кейсов в `var/demo/`. Откройте `var/demo/01_ok.html`. Без установки можно посмотреть готовые карточки: [01](docs/demo/01_ok.html), [05](docs/demo/05_director_changed.html), [10](docs/demo/10_old_director_poa.html), [14](docs/demo/14_old_director_charter_cleared.html). Сценарий показа — [docs/DEMO.md](docs/DEMO.md), все команды и API — [docs/RUN.md](docs/RUN.md).

### В Docker

```bash
cp .env.example .env
# в .env: MANDAT_ENV=demo и MANDAT_API_TOKEN=<длинный случайный токен>
docker compose up --build
curl http://127.0.0.1:8000/health
```

Без `MANDAT_ENV` compose не стартует. В `pilot` и `prod` нужны ещё `MANDAT_JOURNAL_KEY` и `MANDAT_PII_KEY` (по 32 байта и длиннее, см. [docs/KEYS.md](docs/KEYS.md)).

### Пилотный оверлей compose (проверка конфигурации)

```bash
docker compose -f docker-compose.yml -f deploy/compose.pilot.yml up --build --wait
curl http://127.0.0.1:8000/readyz   # 200 только если журнал, хранилище и ключи в порядке; иначе 503
```

Оверлей кладёт `/app/var` на постоянный том, ставит `MANDAT_ENV=pilot` и проверяет готовность по `/readyz`. `/health` показывает только то, что процесс жив. Это проверка конфигурации, не пилот: внешнего якоря журнала, резервного копирования, TLS и смены ключей здесь нет, а журнал и хранилище пишутся отдельно без общей транзакции ([LIMITS.md](LIMITS.md)).

## От стенда к пилоту

Ядро проверки, мониторинг и журнал работают. Пилот подключает к ним источники банка: для реестра МЧД, ЕФРСБ и подписи — адаптер к готовому порту, для ЕГРЮЛ — новый порт по тому же образцу; ядро не переделывается.

| Что подключаем | Сейчас | Шаг к пилоту | Кто |
|---|---|---|---|
| Реестр МЧД, ЕГРЮЛ (Единый государственный реестр юридических лиц), ЕФРСБ (реестр сведений о банкротстве) | реестр МЧД и ЕФРСБ — через порты с данными из кейса; ЕГРЮЛ — выписка из пакета кейса | адаптеры к сервисам банка или СМЭВ | команда и ИТ банка |
| КЭП (квалифицированная электронная подпись) | порт `SignaturePort`, без СКЗИ статус «не проверено», в `strict` это блокирует «подтверждено» | подключить СКЗИ (средство криптографической защиты информации) банка | ИБ банка |
| Правила | 39 правил в статусе `draft`, у каждого норма | утверждение юристом, [вопросы готовы](docs/LEGAL_REVIEW.md) | юрист банка |
| Формат МЧД | сверен с XSD EMCHD_1 по двум совпадающим открытым копиям | сверка со схемой от оператора реестра | команда |
| Точность на реальном потоке | синтетический корпус с заданными дефектами | 50–100 обезличенных пакетов, теневой режим 6 недель ([пилот](docs/PILOT.md)) | владелец процесса |

Ступени готовности: [docs/audit/READINESS_GATES.md](docs/audit/READINESS_GATES.md), полные границы: [LIMITS.md](LIMITS.md).

| C-02 | 14 демо-кейсов, все дают ожидаемый вердикт; «подтверждено» — один (кейс 14) | данные вымышлены |

| C-05 | без человека решается 38,8 % корпуса, ошибок среди них нет (верхняя граница 3,2 %) | в профиле `strict` доля 0 %: без подписи и утверждённых правил всё уходит человеку |
| C-06 | передоверие не шире родительской МЧД на всех 384 двухзвенных цепочках; вторая, независимая реализация правил на языке политик Cedar даёт те же решения | перебор малого домена, а не доказательство для любых входов |
| C-13 | 1491 автотест проходят | — |
| C-17 | 8814 мутаций сценариев: ложных «подтверждено» и падений нет | мутации построены от наших базовых сценариев |
| C-14 | проверка одного кейса — около 2 мс (медиана), 95 % кейсов быстрее 3 мс | машина разработчика, без сети и модели; на другой машине числа другие |

## Трудные вопросы

| Вопрос | Короткий ответ | Где подробно |
|---|---|---|
| 294 из 294 — это точность 100 %? | Нет. Это совпадение с дефектами, которые мы сами заложили в генератор. Точность на потоке банка не измерялась | [оценка](docs/EVALUATION.md) |
| Почему в демо одно «подтверждено»? | Так задумано: при любом сомнении кейс идёт человеку. Цель — ни одного ложного «да». На корпусе без человека решается 38,8 % кейсов, и среди них ошибок нет | [оценка](docs/EVALUATION.md) |
| Реестр ФНС уже показывает статус МЧД. Зачем вы? | Статус реестра — одно правило из 39. Рядом смена руководителя, передоверие, сроки, устав и покрытие конкретной операции | [конкуренты](docs/COMPETITORS.md) |
| Решение принимает ИИ? | Нет. Вердикт выносят правила, модель только предлагает цитату из устава, без цитаты факта нет | [ADR-001](docs/adr/ADR-001-verdict-ownership.md), [риски ИИ](docs/AI_RISKS.md) |
| КЭП проверяется? | Через СКЗИ банка: порт `SignaturePort` готов. Пока СКЗИ не подключено, статус подписи — «не проверено», и в `strict` «подтверждено» не выдаётся | [границы](LIMITS.md#внешние-системы) |
| Формат МЧД сверен с официальной схемой? | С XSD EMCHD_1 (ГНИВЦ ФНС) по двум открытым копиям с одинаковым хешем. На сайте ФНС эта схема не опубликована, поэтому к пилоту сверяем её с оператором реестра. Теги вынесены в файл соответствия, правка без изменения кода | [формат](docs/FORMAT_NOTES.md) |
| Кто отвечает за правила юридически? | Юрист банка на пилоте. Для него уже готово: все 39 правил — черновики со ссылкой на норму и списком вопросов. До его утверждения профиль `strict` не выносит по ним ни «да», ни «нет» | [вопросы юристу](docs/LEGAL_REVIEW.md), [трассировка норм](docs/audit/LEGAL_TRACEABILITY.md) |
| Кто отвечает, если «Мандат» ошибочно скажет «подтверждено»? | Решение об операции принимает банк по своему регламенту, «Мандат» его готовит. За норму в правиле отвечает юрист банка, который его утвердил, а мы — за то, что код исполняет правило так, как оно записано: это закреплено автотестами. Каждый вывод хранит ссылки на норму и поле документа и пишется в журнал, который нельзя незаметно изменить, поэтому ошибку можно разобрать до конкретного правила | [журнал](docs/ARCHITECTURE.md), [план исправлений](docs/REMEDIATION_PLAN_2026-10.md) |
| Зачем правила-черновики работают в `strict`? | Чтобы банк уже сейчас видел все возражения и пробелы по кейсу. Черновик в `strict` не выносит решения: его «да» становится «не проверено», его «нет» — поводом для разбора человеком. Поэтому до утверждения правил юристом `strict` ничего не подтверждает автоматически | [правила](docs/RULES.md) |
| Как система узнает об отмене доверенности у нотариуса? | Сейчас никак: «Мандат» смотрит реестр МЧД ФНС. Отмена через реестр распоряжений нотариата или публикацией (ст. 189 ГК РФ) — отдельный источник, его подключение запланировано на пилот. До этого `strict` такой кейс не подтверждает: все правила пока черновики | [правовые пробелы](docs/REMEDIATION_PLAN_2026-10.md#известные-правовые-пробелы) |
| Смена директора гасит доверенности? | Нет (п. 1 ст. 188 ГК РФ). Давняя смена — сигнал, свежая — повод для разбора | [ADR-002](docs/adr/ADR-002-director-change.md), [нормы](docs/REGULATORY.md) |
| Персональные данные, 152-ФЗ? | Ядро не ходит во внешнюю сеть. В модель уходят строки устава о полномочиях: ФИО становятся метками, дата рождения и адрес человека вырезаются, номера становятся псевдонимами. Сумма сделки остаётся. Фамилия без подсказки может остаться. Оценку соответствия мы не проходили | [что видит модель](#что-видит-модель), [защита данных](docs/DATA_PROTECTION.md) |
| Удостоверение — это ГОСТ-подпись или W3C VC (проверяемое цифровое удостоверение по стандарту консорциума W3C)? | Модель данных W3C VC 2.0 с подписью Ed25519 по образцу Data Integrity и статусами по W3C Bitstring Status List. В пилоте подпись меняется на ГОСТ через СКЗИ банка; совместимость с внешними верификаторами VC не проверялась | [границы](LIMITS.md#безопасность-и-защита-данных) |
| Откуда экономический эффект? | Данные Банка России о хищениях и число клиентов ВТБ взяты из открытых источников. Доли событий, минуты на кейс и долю ВТБ мы задали сами, источника у них нет. Поэтому это сценарии, а не прогноз | [экономика](docs/ECONOMICS.md), C-15 и C-16 в [реестре](CLAIMS_REGISTRY.md) |
| Почему демо-кейс «01_ok» не «подтверждено»? | МЧД, ЕГРЮЛ и представитель сходятся, но шаблоны не смогли сказать, есть ли в уставе ограничения. Для подписи платежей устав обязателен, поэтому без разобранного устава «да» не будет и кейс идёт человеку (правило R-CHR-002) | [сценарий показа](docs/DEMO.md), [правила](docs/RULES.md) |
| Что будет, если реестр МЧД не ответил? | «Недостаточно данных», а не «действует». Молчание источника не считается хорошей новостью | [границы](LIMITS.md#внешние-системы) |
| Чем это отличается от правил в автоматизированной банковской системе (АБС)? | У каждого вывода есть норма и поле документа, свойство передоверия перепроверено независимой реализацией, решение записано в журнал и выдаётся удостоверением с отзывом | [конкуренты](docs/COMPETITORS.md) |
| Что нужно от банка для пилота? | Владелец процесса, регламент одной операции, 50–100 обезличенных пакетов, выгрузка классификатора, юрист для утверждения правил | [пилот](docs/PILOT.md) |
